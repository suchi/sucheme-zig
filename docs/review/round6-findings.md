# 6巡目の自己敵対的レビューの指摘一覧

実施日: 2026-10-05。対象は PR #1 の設計ドキュメント全体。設計の意図を渡さないサブエージェント3体に領域を分けて実行させた([ADR-0017](../adr/0017-self-hosted-adversarial-review.md))。

指摘は107件(必須44・推奨52・任意11)。巡ごとの件数の推移は [adversarial-review-baseline.md](adversarial-review-baseline.md) にある。

この巡のレビューは前の5巡より深い。付録Aのエクスポート238件を機械抽出して網羅主張と突き合わせ、Zig 0.17.0 の実機コンパイルを8回以上行い、GitHub Actions のランナー構成を公式ドキュメントで確認している。指摘の多くはこの巡で書いた文ではなく、前の5巡が見落としていた既存の記述にある。レビューの質が上がった結果である。

本ファイルは、どの指摘をどう処理したかの記録である。[ADR-0018](../adr/0018-incremental-vertical-slices.md) は「記録せずに閉じない」ことを要求している。

## 処理の区分

| 区分 | 意味 |
| --- | --- |
| 設計を直す | 全体整合性に必要な決定の誤りまたは欠落。設計ドキュメントで直す |
| 実装時に決める | 1つのモジュールに閉じた詳細。[../design/open-questions.md](../design/open-questions.md) に記録して閉じる |
| テストで検査する | 散文で主張するより、失敗するテストを先に書くほうが確実なもの。段階の作業項目にする |

## 両方向照合で成果物が正しかったもの

レビュー側の記憶が誤っていた例も記録する。[SKILL.md](../../.agents/skills/adversarial-review/SKILL.md) の「照合は両方向に行う」に対応する。

- R7RS 7.1.1 の `<string element>` が `\|` を列挙していること(外部レビューの指摘が誤りだった件の再確認)
- `(real? -2.5+0i)` が `#t` であること、`equal?` の引用、12個の破壊的操作の一覧、`full-unicode` の定義文がいずれも原文のまま
- 破壊的操作12個、動的点の種別4つ、R7RS 3.5 の末尾呼び出し4箇所、付録Aのライブラリ16件、エクスポート2群の5+8=13、検出器ごとの件数43件の内訳が、独立の数え上げと完全一致

## 検出器の追加候補

カタログ外の探索で見つかった類型。スキルの更新候補として記録する。

- 段階・順序の依存: 完了条件が参照する一覧の各項目について、それを成立させるために必要な記法・値の種類・手続きが同じ段階以前に導入されているか。
- 参考実装からの資源の逆算: 仕様が参考実装を与えている機構について、その参考実装が要求する確保・呼び出し・捕捉を数え上げて設計の資源見積りと突き合わせる。
- 仕様の沈黙の確認: 成果物が「仕様が沈黙している」「原文の中で一貫していない」と述べている箇所は、沈黙していること自体を原文で確認する。
- 退避案の単位: 準拠範囲を縮小する退避案を書くときは、仕様自身が用意している縮小の単位(オプションのライブラリ、フィーチャ識別子)を数え上げて選択肢に含める。
- 束縛として要求されているものを未束縛として扱っていないか。
- 静的に検出すると宣言した誤りが、同じ言語の正当な機能と区別できるか。
