# 敵対的レビューの基準表

[.agents/skills/adversarial-review/SKILL.md](../../.agents/skills/adversarial-review/SKILL.md) の検出器カタログに添えた実例は、PR #1 で外部のレビューサービス(GitHub Copilot コードレビュー)が挙げた妥当な43件の指摘から取った。本ドキュメントはその対応表である。

カタログはレビュー担当者自身の判断を置き換えるものではなく、既知の類型を取りこぼさないための下限である。実例があるのは「少なくともこの類型は実際に起きる」ことの裏付けであり、探す対象をこの43件の範囲に限るという意味ではない。スキルはカタログ外の探索を手順の一段として要求している。

用途は2つある。検出器が実例に裏付けられていることを示すことと、スキルを更新したときに「この43件を再現できるか」を確かめる基準にすることである。誤りだった1件は、照合を両方向に行う能力(成果物が正しくレビュー側が誤っている場合を見抜くこと)の基準として別に扱う。

## 経緯

PR #1 は設計フェーズの成果物(設計ドキュメント7件、ADR16件、SOW、ロードマップ、オンボーディング)を収めた変更である。コードは含まない。

レビューは8巡し、44件の指摘を受け取った。うち43件が妥当で、1件は指摘自体が仕様の誤読だった(後述)。巡回ごとの受領件数は、10件、4件、3件、4件、9件、8件、1件、4件である。巡1の10件のうち1件が誤りだったので、下の対応表は43行である。指摘のうち約半数は、前の巡で書かれた修正文そのものの欠陥だった。修正は新しい攻撃面であるという教訓はここから来ている。

指摘が集中したのは `docs/design/runtime.md`(18件)と `docs/design/frontend.md`(10件)で、いずれも構造体宣言と手続きの規則を密に書いた文書である。

外部サービスの利用上限に達したため、以降は本スキルによる自前のレビューに切り替えた。切り替えの判断と検証結果は [ADR-0017](../adr/0017-self-hosted-adversarial-review.md) にある。

## 外部レビューの指摘が誤りだった件

受領44件のうち1件(巡1)は指摘が誤りだった。上の対応表には含めていない。文字列のエスケープに `\|` を含めている点について「`\|` は縦棒識別子用で文字列のエスケープには含まれない」という指摘だったが、R7RS 7.1.1 の `<string element>` の生成規則は `\|` を明示的に列挙している。原文を確認して現状を維持し、根拠を `docs/design/frontend.md` に書き添えた。

この件は、照合を両方向に行う必要があることの実例である。レビュー側の記憶が誤っている可能性を常に残す。

## パリティ試験の結果

8巡目を自前レビューとの比較試験に使った。外部サービスの指摘を読む前に、本スキルを用いて設計の背景を渡さないサブエージェントで独立にレビューを実行し、後から突き合わせた。

| 項目 | 外部サービス(8巡目) | 自前レビュー |
| --- | --- | --- |
| 指摘件数 | 4 | 28(必須11・推奨16・任意1) |
| 相手の指摘の捕捉 | - | 4件のうち2件 |
| 相手が挙げなかった指摘 | - | 26件(うち必須9件) |
| 一次情報の照合 | 不明 | R7RS 38箇所、Zig 実機20件以上 |

量と深さでは上回ったが、再現率で2件を取りこぼした。達成とは言えない。

取りこぼした2件は同じ形だった。いずれも、設計が「すべて」または「1箇所に閉じる」と主張している対象集合を、レビュー側が独自に数え上げていなかったことによる。`include` の件は、経路を組み立てる箇所の洗い出しがライブラリ名の経路だけに留まり、ファイル名を受け取る構文からの経路を見落とした。ルート枠の件は、不変条件が「生のヒープポインタも登録する」と要求しているのに対し、提供される API の受付型と突き合わせなかった。

この形は一般化できるため、次をスキルに追加した。

- 原則に「『すべて』『必ず』『1箇所に閉じる』『次に限る』と書かれていたら、その対象集合を自分で数え上げて突き合わせる」を追加した。
- 手順に「網羅主張の数え上げ」の段を、検出器の適用より前に置いた。
- 検出器2に「不変条件の対象型を数え上げて API の引数型と突き合わせたか」を追加した。
- 検出器6に「同じ資源に到達する経路を全部数え上げたか。別の構文や別の API から同じ資源に届く経路があれば検証を迂回する」を追加した。

強化後の再試験の結果は、実施したら本ドキュメントに追記する。切り替えの判断は [ADR-0017](../adr/0017-self-hosted-adversarial-review.md) にある。
