# スライス 7i の敵対的レビューで、直さずに記録した指摘と、受け入れた制約

対象は suchi/sucheme-zig#306(Windows の生モード)。担当は別セッションの1本で、結果は必須 0、推奨 0、任意 3 だった。

## 直したもの

- 任意1: モードのビットと、コードページ、エラー番号の定数を、文書の値のリテラルで固定するテストを足した。
- 任意2: 幅 1 のウィンドウの `visibleColumns` のテストを足した。

## 直さずに記録するもの(任意)

| 番号 | 指摘 | 送り先(提案。決定ではない) |
| --- | --- | --- |
| R1 | コンソールの終了イベントのハンドラ(`onCtrlEvent`)の、イベントの種類の振り分けが、ハンドラの中にあり、単体でテストできない。振り分けだけを純粋な関数に切り出せば、テストできる | `term_windows.zig` を次に触るとき |

## 受け入れた制約(確かめていないこと)

レビューが「見えない」とした点で、実機でしか確かめられない。この環境からは確かめられないので、制約として受け入れる。

- 実機でのキー入力、再描画、終了時のモードの復元。層2 の Windows のジョブは、コンパイルと単体テストだけを通す(コンソールが無い)。
- 入出力のコードページを UTF-8(65001)にしたとき、コンソールの入力の `ReadFile` が ASCII でない文字を正しく返すか。古い Windows 10 に既知の不具合がある、というレビュー担当の記憶があるが、未確認である(一次情報で確かめていない)。
- 終了イベントのハンドラ(別のスレッドで走る)と、`leave` が同時に進むときの振る舞い。ハンドラは、有効かどうかの原子的な値を読んで、保存したモードを書き戻す。`leave` は、書き戻したあとに、有効でない印を付ける。同時に走ると、同じ値の書き戻しが2回起きうるが、書き戻す値は同じである。この読みは設計上のもので、実機では確かめていない。
