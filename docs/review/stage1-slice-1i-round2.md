# スライス 1i(PR #36)の第2巡の敵対的レビューの指摘の処理

実施日: 2026-10-11。対象は PR #36(スライス 1i、WebAssembly の境界と Web UI)で、マージ後に第2巡の指摘を処理した。指摘の重要度は帰結で決める([ADR-0027](../adr/0027-severity-by-consequence-and-a-cost-side-stop.md))。本ファイルへの指摘は任意を上限とする。

## この PR で直したもの

| 番号 | 区分 | 指摘 | 対応 |
| --- | --- | --- | --- |
| R1 | 推奨 | ホストの上限の丸め(`heap.max_host_limit`、`clampHostLimit`、`sucheme_init`)に回帰テストが無い | `heap.hostOptions` に出して単体テストで固定した。上限に届く実挙動は `zig build test-wasm -Dslow=true` で確かめる |
| R2 | 推奨 | `tools/test-wasm/main.mjs` が `URL.pathname` をファイルパスに使っており、空白や非 ASCII を含むパスで落ちる | `fileURLToPath` に替えた。空白と日本語を含むディレクトリの複製で、直す前に落ち、直した後に通ることを確かめた |
| O3 | 任意 | 設計文書の「関数ごとに返しうる値」の表と 1i の計画書に、`sucheme_reset` が初期化前に -5 を返すことが無い | 表を実装に合わせた |
| O4 | 任意 | `spawnSync` に `timeout` が無い | 30 秒を付けた |

## 直さずに記録するもの(任意)

内容は第2巡のレビュアの報告による。O の番号は報告の番号に合わせてある。この PR では実機で再現していない(O1 と O8 は、`src/wasm.zig` を読んで確かめた)。

| 番号 | 指摘 | 処理 |
| --- | --- | --- |
| O1 | 出力バッファが満杯のとき、`appendTail` が手前の出力の末尾をバイト単位で削るので、削った境界で UTF-8 の文字が途中で切れうる | 後のスライスで、出力の境界を文字に揃えるかを決める |
| O2 | 初期化前の `early_buffer`(512 バイト)も同じ削り方をするので、複数の説明が重なると断片が残りうる | O1 と同じ。初期化前に残る説明は短い |
| O5 | `web/serve.mjs` が zip を平置きにしたときの警告が、実際の配置と食い違う | 配布の形が決まるスライスで直す |
| O6 | http で `sucheme.wasm` が 404 のとき、`file://` で開いた場合の案内が出る | `web/` の配信の整理と一緒に直す |
| O7 | favicon が 404 になる | `web/` の整理と一緒に直す |
| O8 | `sucheme_reset` の再初期化が確保に失敗する経路(-7)は、出力に説明を書かずに戻る。ホストは -7 だけで原因を知る。コードを読んで気づいたもので、レビュアの指摘ではない | 後のスライスで、`appendTail` で一行を残すかを決める |

## やり残し

- 上限に届く確認(R1 の実挙動、約1分)は、`build.zig` が `-Dslow=true` のときだけ環境変数 `SUCHEME_SLOW` を渡して走らせる。`full.yml` に `zig build test-wasm -Dslow=true` の step を足した(ユーザーが 2026-10-11 に承認した)。検証コマンド表の「規模を試すもの」の行にも足した。
