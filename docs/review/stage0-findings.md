巡番号は PR ごとに別の系列である。本ファイルの「N巡目」は PR #2 のもので、[round6-findings.md](round6-findings.md) の「6巡目」は PR #1(設計ドキュメント)の系列を指す。コミットメッセージが参照する巡番号は、そのコミットが属する PR の系列に従う。

## 繰り返し現れた類型

同じ原因が巡をまたいで再発したものを記録する。[ADR-0018](../adr/0018-incremental-vertical-slices.md) は「記録せずに閉じない」ことを要求している。

### 検査する行が任意のテキストも運べる

`tools/check-docs` のワークフロー検査で、`setup-zig@` の段から版を読む経路が囮の運び手を4回替えながら生き延びた。

| 巡 | 囮の置き場所 |
| --- | --- |
| 4 | `uses:` 行の末尾コメントの `version:` |
| 5 | フロー写像の `name:` の値に置いた `version:`(本物より前) |
| 6 | `name:` の値だけに置いた `version:`(本物は無い) |
| 7 | 別のジョブの `strategy.matrix` の `version` 次元 |

4巡目から6巡目はいずれも「読む条件を狭める」形の修正で、そのたびに次の運び手が現れた。閉じたのは、アクションを名指す行から版を読むこと自体をやめ(6巡目)、版を段の字下げに対応づけた(7巡目)ときである。教訓は、入力の形を列挙して弾くのではなく、読む対象を構造で限定することにある。

### 個数の一致を対応の代理にしている

2箇所で同じ誤りをした。

- `checkTestsAreRun` が run 段の個数を数え、どの run 段がどの test バイナリかを見ていなかった(6巡目に導入、7巡目に指摘)。run 段を別の成果物に向けると個数は保たれる。
- `workflowZigVersions` が版を平らな一覧で返し、呼び出し側が段数と版数を比べていた(7巡目まで、8巡目に指摘)。2段あると片方の版が両方を満たす。版を段ごとに持たせて直した。
- `checkRecordedCounts` が「ファイル → 表の行」の一方向だけを照合し、行数とファイル数を見ていなかった(6巡目に導入、7巡目に指摘)。ファイルを消して記録を貼り替えると通る。

どちらも集合の対応を主張しながら個数を比べていた。個数は要素を入れ替えても保たれる。

### 主張を書いた箇所と、検査する箇所が一致しない

doc コメントや文書に「こうなっている」と書き、その主張を機械が検査していないまま次の巡で指摘された。

- 「追加・削除・改名も値を変える」(生成物の一括ハッシュ)— 符号化が単射でなかった(5巡目に主張、6巡目に指摘)
- 「無視集合の家は `.gitignore` 1つ」— `skipped_dirs` が重複して持っていた(6巡目に主張、7巡目に指摘)
- 「`collectFiles` も無視集合を取る」— 取っていなかった(7巡目に主張、同じ巡の実機確認で発覚)
- 「どちらも open-questions.md に記録した」(`refAllDecls` の2つの限界)— 1件しか記録していなかった(3巡目に主張、4巡目に指摘)

7巡目のレビューはこの類型について「基準を下げずに巡回数を減らす余地は、主張をコードに移す側にある」と述べた。実際に移したものが2件ある。引用ブロックの lazy continuation の検出と、識別子数の表の照合である。前者は足した直後に、同じ修正の最中に書いた同じ誤りを捕まえた。

### 同じ事実を述べる箇所を数え上げていない

ライセンスの変更で、第三者由来のものの列挙を `LICENSE` と ADR-0022 の2箇所で直し、同じ列挙を持つ README を数え上げなかった(6巡目に修正、7巡目に指摘)。スキルの修正の規律2が要求している手順を踏んでいなかった。

## 検出器の追加候補

7巡目までにカタログ外で見つかった類型。[SKILL.md](../../.agents/skills/adversarial-review/SKILL.md) の更新に回す。

- 引用した原文から導いた結論を、同じ原文の別の文が否定していないか。引用が原文どおりであることと、そこから導いた推論が妥当であることは別である。
- 直前の巡の修正が、同じ事実を述べる箇所を全部覆ったかを独立に数え上げる。
- 文書とコミットメッセージが参照する連番・巡番号・版番号が、1つの系列を指すか。
- 対応を検査すると宣言している箇所が、要素の対応を見ているか、個数を比べているだけか。
- 機械検査の対象集合と、追跡外ファイルの無視集合のずれ。検査が「ここに X 以外は無い」と主張するとき、処理系・OS・エディタが作るものが無視集合に入っているか。
- 「N 個走る」ことを個数で検査する機構に、個数が一致したまま中身が空になる入力があるか。
- 許諾・公開状態を変える決定について、変更前の状態で成果物が外部に出た期間があるかを履歴から数え上げる。取り消せない過去を「状態をなくす」と書いていないか。
- リポジトリ内の全コード断片について、その言語の最小の構文的健全性(括弧と引用符の対応)を機械的に照合する。
