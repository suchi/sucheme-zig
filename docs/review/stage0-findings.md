対象は段階0の足場(`build.zig`、CI、`tools/check-docs`、`tools/extract-r7rs-required`、および段階0で書いた文書)。設計の意図を渡さないサブエージェントに1巡ずつ実行させた([ADR-0017](../adr/0017-self-hosted-adversarial-review.md))。

巡番号は PR ごとに別の系列である。本ファイルの「N巡目」は PR #2 のもので、[round6-findings.md](round6-findings.md) の「6巡目」は PR #1(設計ドキュメント)の系列を指す。コミットメッセージが参照する巡番号は、そのコミットが属する PR の系列に従う。

## 巡ごとの指摘

内訳だけを置く。指摘数の列と対応欄は、内訳と各巡の節の状態欄から導けるので落とした。導ける数を2箇所に書くと、食い違いが指摘として湧く([ADR-0027](../adr/0027-severity-by-consequence-and-a-cost-side-stop.md))。各指摘の処理状況は、巡ごとの節の状態欄が正である。1巡目は内訳を記録していない。8巡目までは推奨と任意も同じ巡で全件処理したので、未処理分の節が無い。

16巡目で方針を変えた。詳細は [ADR-0026](../adr/0026-verify-facts-about-code-not-prose.md) にある。文書の書き方を見る検査を撤回したので、それらの検査についての指摘と、過去の巡で段階1へ回していた作業項目のうちその検査に属するものは、作業として消える。消えた項目は下の節に「検査の撤回で消滅」と記録する。破棄ではなく、守る対象をやめたという記録である。

16巡目の必須のうち残ったのは3件である。`adrRowStatus` と `rowCounts` がエスケープしたパイプで別のセルを読んでいた件(`cellAt` に通して解消)、`space_spellings` の doc コメントが自分の集合について偽だった件(配列ごと撤回)、`protect-config.sh` が Bash に登録されていない件(設定の適用で解消)。必須1(表の範囲の打ち切り)と必須4(コロンの字形)は、該当の検査を撤回したので対象が無くなった。

下降が単調ではない。各巡の指摘の大半が直前の巡で書いた修正文そのものの欠陥であり、修正が新しい表面積を作る。7巡目が増えたのは、6巡目でライセンスの変更(MIT から UNLICENSED へ、[ADR-0022](../adr/0022-unlicensed-proprietary.md))と ADR の運用ルールの改訂という実質的な変更を加えたためである。

本表の7巡目の件数は当初17と書いていたが、内訳(7+10+3)と合わなかった。20が正である。合計と内訳を持つ表は全行で算術が合うことを確かめる。

15巡目の必須も4件が同じ類型だった。ADR 一覧の行を記録として数えていなかったこと、検証コマンド表のセルを正規化せず読めないセルを黙って捨てていたこと、複数行の平スカラーで書いた `run:` の継続行を読み飛ばしていたこと、GFM の表の開始と継続の規則に合っていなかったことである。5件目は実装を変えた巡が doc コメントと帳簿を更新しなかったものである。

2巡続いたので、[ADR-0024](../adr/0024-closed-spelling-sets.md) の見直し条件に当たる。ただし15巡目の4件は「綴りの集合を広げる」ものではなく「宣言した規則を適用する範囲が狭かった」ものである。ADR-0024 が閉じると宣言した正規化を表のセルが通っておらず、報告すると宣言した記録に ADR 一覧の行が入っていなかった。パーサを入れても、適用範囲の数え上げ漏れは同じように起きる。したがってパーサの判断をユーザーに諮る前に、宣言と適用範囲の突き合わせを検出器として使い切る。16巡目で同じ類型が「綴りを追いかける」側で出た場合は、見直し条件に従って選択肢を提示する。

14巡目の必須は、全件が「手書きのパーサが CommonMark と GFM の綴りに追いついていない」ものだった。Unicode の空白とゼロ幅文字、箇条書きの中の4スペース、字下げしたフェンス、行の途中の HTML コメント、先頭と末尾のパイプである。規則を広げる形で閉じ、閉じた範囲と閉じていない範囲を [ADR-0024](../adr/0024-closed-spelling-sets.md) と [../design/open-questions.md](../design/open-questions.md) に書いた。同じ類型が次の巡でも必須で出る場合は、ADR-0024 の見直し条件に従ってパーサを依存に加えるかをユーザーに確認する。

9巡目から収束条件が「必須の新規指摘ゼロ」になった([ADR-0023](../adr/0023-mandatory-zero-convergence.md))。推奨と任意は本ファイルに記録して該当する段階の作業項目に回す。回した内容は下の「段階1へ回した推奨と任意」にある。

### 20巡目を ADR-0027 の帯で採点し直した結果

[ADR-0027](../adr/0027-severity-by-consequence-and-a-cost-side-stop.md) は重要度を帰結で定めた。20巡目の必須18件をその帯で採点し直すと、帰結(1)(2)(3)に当たるのは3件である。

| 件 | 帰結 | 理由 |
| --- | --- | --- |
| 20a-必須3 | (1) 検証が黙って止まる | `captureStdOut` で run がキャッシュ可能になり、文書を壊しても再実行されない |
| 20a-必須4 | (1) 検証が黙って止まる | 1行で閉じない行内リンクが診断なしに検査から外れる |
| 20a-必須6 | (1) 検証が黙って止まる | 字下げしたフェンス対が間の段落をリンク検査から外し、閉じ忘れの診断も出ない |

残る15件の帯は次のとおりで、いずれもマージの門を塞がない。

- 20a-必須1・20a-必須2: `build.zig` の中の守りを `build.zig` の編集で無効にする類型。ADR-0026 が原理的な限界として線を引いた。
- 20a-必須5・20b-必須1〜5: 人が依存している記録の誤り(計画書・ADR・SOURCE.md)。推奨の帯。
- 20a-必須7〜9・20b-必須6〜9: 帳簿の数え上げと状態欄。ADR-0027 が任意を上限と定めた帯。導ける列を落としたので、この供給源そのものが無くなった。

3件はいずれも20巡目で直し、実機で赤になることを確認した。したがって **ADR-0027 の収束条件のもとで、20巡目をもって収束している。** 残る指摘は推奨と任意の帯として段階1へ回す。

採点し直す前に20巡目の時点でこれをやっていれば、巡回は16巡目あたりで止まっていた。巡を足すことが既定の行動になっていた理由は、重要度が帰結ではなく種類で決まっていたことである。

## 繰り返し現れた類型

同じ原因が巡をまたいで再発したものを記録する。[ADR-0018](../adr/0018-incremental-vertical-slices.md) は「記録せずに閉じない」ことを要求している。

### 検査する行が任意のテキストも運べる

`tools/check-docs` のワークフロー検査で、`setup-zig@` の段から版を読む経路が囮の運び手を4回替えながら生き延びた。

| 巡 | 囮の置き場所 |
| --- | --- |
| 4 | `uses:` 行の末尾コメントの `version:` |
| 5 | フロー写像の `name:` の値に置いた `version:`(本物より前) |
| 6 | `name:` の値だけに置いた `version:`(本物は無い) |
| 7 | 別のジョブの `strategy.matrix` の `version` 次元 |

4巡目から6巡目はいずれも「読む条件を狭める」形の修正で、そのたびに次の運び手が現れた。閉じたのは、アクションを名指す行から版を読むこと自体をやめ(6巡目)、版を段の字下げに対応づけた(7巡目)ときである。教訓は、入力の形を列挙して弾くのではなく、読む対象を構造で限定することにある。

### 個数の一致を対応の代理にしている

2箇所で同じ誤りをした。

- `checkTestsAreRun` が run 段の個数を数え、どの run 段がどの test バイナリかを見ていなかった(6巡目に導入、7巡目に指摘)。run 段を別の成果物に向けると個数は保たれる。
- `workflowZigVersions` が版を平らな一覧で返し、呼び出し側が段数と版数を比べていた(7巡目まで、8巡目に指摘)。2段あると片方の版が両方を満たす。版を段ごとに持たせて直した。
- `checkRecordedCounts` が「ファイル → 表の行」の一方向だけを照合し、行数とファイル数を見ていなかった(6巡目に導入、7巡目に指摘)。ファイルを消して記録を貼り替えると通る。

どちらも集合の対応を主張しながら個数を比べていた。個数は要素を入れ替えても保たれる。

### 主張を書いた箇所と、検査する箇所が一致しない

doc コメントや文書に「こうなっている」と書き、その主張を機械が検査していないまま次の巡で指摘された。

- 「追加・削除・改名も値を変える」(生成物の一括ハッシュ)— 符号化が単射でなかった(5巡目に主張、6巡目に指摘)
- 「無視集合の家は `.gitignore` 1つ」— `skipped_dirs` が重複して持っていた(6巡目に主張、7巡目に指摘)
- 「`collectFiles` も無視集合を取る」— 取っていなかった(7巡目に主張、同じ巡の実機確認で発覚)
- 「どちらも open-questions.md に記録した」(`refAllDecls` の2つの限界)— 1件しか記録していなかった(3巡目に主張、4巡目に指摘)

7巡目のレビューはこの類型について「基準を下げずに巡回数を減らす余地は、主張をコードに移す側にある」と述べた。実際に移したものが2件ある。引用ブロックの lazy continuation の検出と、識別子数の表の照合である。前者は足した直後に、同じ修正の最中に書いた同じ誤りを捕まえた。

### 同じ事実を述べる箇所を数え上げていない

ライセンスの変更で、第三者由来のものの列挙を `LICENSE` と ADR-0022 の2箇所で直し、同じ列挙を持つ README を数え上げなかった(6巡目に修正、7巡目に指摘)。スキルの修正の規律2が要求している手順を踏んでいなかった。

## 検出器の追加候補

7巡目までにカタログ外で見つかった類型。[SKILL.md](../../.agents/skills/adversarial-review/SKILL.md) の更新に回す。

- 引用した原文から導いた結論を、同じ原文の別の文が否定していないか。引用が原文どおりであることと、そこから導いた推論が妥当であることは別である。
- 直前の巡の修正が、同じ事実を述べる箇所を全部覆ったかを独立に数え上げる。
- 文書とコミットメッセージが参照する連番・巡番号・版番号が、1つの系列を指すか。
- 対応を検査すると宣言している箇所が、要素の対応を見ているか、個数を比べているだけか。
- 機械検査の対象集合と、追跡外ファイルの無視集合のずれ。検査が「ここに X 以外は無い」と主張するとき、処理系・OS・エディタが作るものが無視集合に入っているか。
- 「N 個走る」ことを個数で検査する機構に、個数が一致したまま中身が空になる入力があるか。
- 許諾・公開状態を変える決定について、変更前の状態で成果物が外部に出た期間があるかを履歴から数え上げる。取り消せない過去を「状態をなくす」と書いていないか。
- リポジトリ内の全コード断片について、その言語の最小の構文的健全性(括弧と引用符の対応)を機械的に照合する。
