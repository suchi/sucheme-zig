# sucheme v0.5.0

sucheme-zig の5つ目のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階5(ポートと入出力)にあたる。ポート、`display` と `write`、ファイルの入出力、`read`、`eval`、`load`、`exit` と、R7RS 付録Aのライブラリすべてがそろった。段階5の大部分は v0.4.0 に先に入っていて、v0.4.0 からの違いは、`current-error-port` への書き込みが標準エラーに出るようになったことである。R7RS-small の準拠を名乗れる段階ではない(準拠検証は段階6)。どこまで動くかの正は [docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/roadmap.md) の「現在地」と、生成物の [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/status/conformance.md) である。ここには数を書き写さない。

ライセンスは付与していない(UNLICENSED、全権利保留。[ADR-0022](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/adr/0022-unlicensed-proprietary.md))。

## v0.4.0 からの変更

- ネイティブの REPL とファイルの実行で、`current-error-port` への書き込みが標準エラーに出るようになった。v0.4.0 では標準出力に出ていた。書くたびに、先にそれまでの標準出力への出力を書き出すので、端末の上ではプログラムが書いた順に並ぶ。Web UI では、v0.4.0 と同じく、結果と同じ欄に出る。

## 取得の確認

ダウンロードしたファイルが壊れていないことは、`SHA256SUMS` と同じディレクトリで次を実行して確かめる。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v0.5.0-x86_64-linux-musl.tar.gz
./sucheme-v0.5.0-x86_64-linux-musl/sucheme --version         # sucheme 0.5.0
./sucheme-v0.5.0-x86_64-linux-musl/sucheme                   # REPL
./sucheme-v0.5.0-x86_64-linux-musl/sucheme prog.scm a b      # ファイルのプログラムを、引数 a b を渡して実行する
./sucheme-v0.5.0-x86_64-linux-musl/sucheme -I lib prog.scm   # ライブラリの探索ルートを足す
```

引数なしで起動すると、標準入力が尽きるまで REPL が動く。終えるには、標準入力を閉じる(Linux と macOS の端末では Ctrl-D)か、`(import (scheme process-context))` のあとで `(exit)` を呼ぶ。

REPL とファイルのプログラムの最初の環境は、`(scheme base)` である。`display` と `write` は `(scheme write)`、`sqrt` や `exp` は `(scheme inexact)`、`exit` と `command-line` は `(scheme process-context)` にあるので、使う前に `import` する。

```scheme
(import (scheme base) (scheme write))
(display (/ 1 3)) (newline)                       ; 1/3
(write-string "warning\n" (current-error-port))   ; 標準エラーに出る
```

ファイル名を渡すと、そのファイルのプログラムを先頭から評価する。式の値は出力せず、プログラムが現在の出力ポートに書いたもの(`display`、`write-string` など)が標準出力に、現在のエラーポートに書いたものが標準エラーに出る。プログラムの `read` や `read-char` は標準入力から読む。終了ステータスは、最後まで実行すれば 0、実行時エラーで止まれば 1(stderr に `error: ` と説明を出す)、ファイルを読めなければ 66、プログラムが `exit` を呼べばその引数から決まる値である。標準入力のプログラム(`-`)は未実装で、69 で終了する。コマンドラインと終了ステータスの契約は `src/main.zig` の doc コメントが正である。

`-I <dir>` と `include` の探索の規則は v0.4.0 と同じである。`load` も、同じ探索ルートの規則でファイルを開く(名前は、いつも作業ディレクトリを基準にする)。プログラムが開くファイル(`open-input-file` など)は、探索ルートに制約されない。

Web UI は、アーカイブを展開したディレクトリで `node serve.mjs` を実行し、表示された `http://127.0.0.1:<ポート>/` をブラウザで開く。`file://` で開いても動かない([ADR-0021](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/adr/0021-no-github-pages-defer-hosting.md))。Web UI には、選んで実行できるサンプルが6個あり、入力したソースを URL のフラグメント(`#code=...`)に入れた共有リンクを作れる。Web UI では、`display` などの出力も、エラーポートへの出力も、結果と同じ欄に出る。ファイルは開けず(`file-error` になる)、標準入力は最初から終わりにある。

## できること

v0.4.0 で動いたものはすべて動く。段階5の全体は次のとおりである(段階4までの数と Unicode の機能は、[v0.4.0 のリリースノート](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/releases/v0.4.0.md)にある)。

- ポート: 文字列ポート、バイトベクタポート、ファイルポート(`(scheme file)`)、コンソールのポート。`current-input-port`、`current-output-port`、`current-error-port` は `parameterize` で差し替えられる。`read-char`、`peek-char`、`read-line`、`read-string`、`read-u8`、`write-char`、`write-string`、`write-u8` などと、`call-with-port`、`with-output-to-file` などの手続き。ネイティブでは、エラーポートは標準エラーに書く。
- `(scheme write)`: `display`、`write`、`write-shared`、`write-simple`。`write` は、循環したデータをデータラベル(`#0=` と `#0#`)つきで書き、止まる。REPL の結果の印字も、循環したデータで止まる。
- `(scheme read)`: `read`。読めない入力では `read-error?` が真になる条件を送出する。`#!fold-case` はポートごとに効く。
- リーダ: ブロックコメント、データのコメント `#;`、`#!fold-case` と `#!no-fold-case`(同じ入力の途中で効く)、縦棒で囲んだ識別子、データラベル、文字列の行継続。
- `(scheme eval)` と `(scheme repl)`: `eval`、`environment`、`interaction-environment`。
- `(scheme load)`: `load`。ファイルの形式を1つずつ展開して走らせ、前の形式の定義とマクロが次の形式に効く。
- `(scheme process-context)`: `exit`(`dynamic-wind` の `after` を呼んでから終わる)、`emergency-exit`、`command-line`、`get-environment-variable`、`get-environment-variables`。
- `(scheme time)`: `current-second`、`current-jiffy`、`jiffies-per-second`。
- `(scheme r5rs)`: R5RS の識別子と、`exact->inexact`、`inexact->exact`、`scheme-report-environment`、`null-environment`。これで、R7RS 付録Aのライブラリはすべて `import` できる。
- 展開時のエラーには、ライブラリのファイルと、`include` が読むファイルの中でも、`prog.scm:2:3: ` のようにファイルと行と桁を前置する。

## できないこと

このリリースでは、次は動かない。いずれも後の段階で入る([docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/roadmap.md))。

- 実行時のエラー(展開のあとのエラー)には、位置が付かない。`load` が読み込んだ形式と、`eval` に渡したデータの展開のエラーにも、位置は付かない。
- 標準入力のプログラム(`-`)。
- REPL の行編集(カーソル移動、履歴、補完)。

次の既知の制限がある。いずれも結果は決めた形で返るもので、後の段階で直すかどうかを決める。

入出力と REPL:

- REPL では、`#!fold-case` が、それを書いた行の後の行に引き継がれない。同じ行の中では効く。REPL は1行(閉じていない式は、閉じるまでの複数行)ごとに新しい読み手で読み、畳み込みの状態を持ち越さないためである。R7RS 2.1 は、ディレクティブが同じポートから読む後続のデータに効くとしているので、REPL の入力をコンソールのポートからの読み取りと見るなら、準拠の欠落である。ファイルの実行は、ファイルの全体を1回で読むので、ファイルの中では効く。Web UI も、1回の実行に渡したソースの中では効くが、次の実行には引き継がれない。`read` が読むポートでは、ポートごとに引き継がれる。段階6で直す。
- 標準エラーが閉じているか書けないとき(`sucheme prog.scm 2>&-`、`2>/dev/full`)、プログラムが `current-error-port` に書いた時点で実行が打ち切られ、終了コード 1 で終わる。診断の書き先も標準エラーなので、何も出ない。REPL でも同じである。
- Web UI では、コンソールの入力は最初から終わりにある。`(read-char)` は EOF を返す。
- コンソールから `read` で読むとき、REPL の読み手のバッファ(1行 65536 バイト)より長いデータは読めない(`datum longer than the input buffer`)。`read` が読めない入力で失敗したあと、ポートはそのデータの頭に留まる。そのため、REPL で `(read)` が `)` で失敗すると、REPL が同じ `)` を読んで、誤りが2回出る。
- R5RS の指数の印(`1s2`、`1f2`、`1d2`、`1l2`)は読まない(`unreadable token`。`string->number` は `#f`)。R7RS は `e` だけを定める。
- `environment`、`scheme-report-environment`、`null-environment` を繰り返し呼ぶと、常駐のメモリが伸び、ヒープの上限に届いても `heap limit exceeded` にならない。v0.5.0 の後に直す。
- ファイルを読むときのリーダの作業領域は、ヒープの上限に数えられない。ファイルは 1 MiB までで、これを超えると読まずに断る。

数と Unicode(v0.4.0 と同じ):

- 正確な数として読む綴り(整数と、`#e` を付けた小数など)の大きさに上限がある。桁は 100,000 個まで、指数の絶対値は 1,000,000 までで、超えると数として読まない(`unreadable token`。`string->number` は `#f`)。不正確な数として読む綴りは、上限を超えても読み、`+inf.0`、`-inf.0` か `0.0` になる。上限の内側でも、`#e1e1000000` のような綴りは1つ読むのに時間がかかり、その値を `write` で十進に書くのは非常に遅い。多倍長整数の演算そのものには、時間の上限が無い。
- `exp` などの初等関数は、最後の桁が1だけずれることがある(`(exp 1)` は `2.7182818284590455`)。複素数の初等関数と2引数の `log` も同じである。符号つきの0の扱いは、C99 の複素数の関数と違うことがある。各部が倍精度の範囲の端に近い複素数では、`asin` などが有限の答えを失うことがある。
- `string-downcase` は、語末のシグマを特別に扱わない(`(string-downcase "ΑΣ")` は `"ασ"`)。
- `#!fold-case` の畳み込みは単純な畳み込みで、`ß` のように完全な畳み込みでだけ変わる文字は畳み込まない。
- `write` は、ASCII でない文字を含むシンボルを縦棒で囲んで書く(`(write 'λ)` は `|λ|`)。読み戻すと同じシンボルになる。

そのほか(v0.4.0 と同じ):

- 準拠スイートには、まだ落ちる項目がある(件数と内訳は [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/status/conformance.md))。
- マクロが導入したトップレベルの `define` と `define-syntax` は、衛生的でない。利用側の同じ綴りのトップレベルの変数を書き換える。R7RS 4.3 は、トップレベルの変数の定義が束縛を導入するかを実装に委ねている。段階6の準拠検証で、直すかを決める。
- パラメータの読み出しは、`parameterize` の入れ子の深さに比例して遅くなる。段階6で見直す。
- 多くの値を返す `values` は、個数に比例する領域を1ステップの中で確保する。段階6で直す。

## 動作保証の範囲

- 実行して確かめた: x86_64 Linux の実行ファイルは、リリースの成果物そのもの(`ReleaseSafe`)を、組み立ての直後に実行して `--version` と階乗の計算を確かめている。テストは Linux x86_64 で、プルリクエストへの push のたびに自動で走る。Windows x86_64 のテストと、規模を試すテストは、プルリクエストを ready にしたときに走る。
- ビルドだけ確かめた: Windows の実行ファイル、macOS(x86_64、aarch64)、Linux aarch64、Windows aarch64。リリースの成果物そのものは、これらの環境で実行して確かめていない。aarch64 の実行は、どこでも確かめていない([ADR-0033](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/adr/0033-aarch64-built-but-not-tested.md))。macOS は、署名も公証もしていない。
- Web UI: ブラウザ自動化のテストは無い。wasm のエクスポートを Node.js から呼ぶラウンドトリップのテストと、サンプルの評価と共有リンクの符号化のテストだけが自動で走る。ブラウザ固有の問題は検出されない。
- 問題が見つかった場合は、issue で知らせてほしい。

## 暫定の値

GC を起動する閾値(割り当ての倍率と最小値)は暫定である。性能は測っておらず、遅い。起動のたびに `(scheme base)` を展開するので、空の入力でも数ミリ秒かかる。ベンチマークは未実施で、準拠テストが通った後の性能の測定で見直す。ヒープの上限に届くと `heap limit exceeded` で止まる([ADR-0031](https://github.com/suchi/sucheme-zig/blob/v0.5.0/docs/adr/0031-gc-at-machine-step-boundaries.md))。
