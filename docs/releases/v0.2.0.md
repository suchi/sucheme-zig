# sucheme v0.2.0

sucheme-zig の2つ目のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階2(コア言語の完成)にあたる。完全な `call/cc` と `dynamic-wind`、例外、衛生的マクロ、ライブラリシステムが入った。R7RS-small の準拠を名乗れる段階ではない。標準ライブラリ(`(scheme base)` など)は、まだ無い。どこまで動くかの正は [docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/roadmap.md) の「現在地」と、生成物の [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/status/conformance.md) である。ここには数を書き写さない。

ライセンスは付与していない(UNLICENSED、全権利保留。[ADR-0022](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/adr/0022-unlicensed-proprietary.md))。

## 取得の確認

ダウンロードしたファイルが壊れていないことは、`SHA256SUMS` と同じディレクトリで次を実行して確かめる。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v0.2.0-x86_64-linux-musl.tar.gz
./sucheme-v0.2.0-x86_64-linux-musl/sucheme --version     # sucheme 0.2.0
./sucheme-v0.2.0-x86_64-linux-musl/sucheme               # REPL
./sucheme-v0.2.0-x86_64-linux-musl/sucheme -I lib        # ライブラリの探索ルートを足す
```

引数なしで起動すると、標準入力が尽きるまで REPL が動く。終えるには、標準入力を閉じる(Linux と macOS の端末では Ctrl-D)。`exit` は無い。プロンプトは `> `、閉じていない式の続きは `... ` である。エラーはその式の評価を終わらせるだけで、REPL は続く。ファイル名を渡しても、ファイルの実行は未実装だと伝えて終了する(終了ステータス 69)。コマンドラインと終了ステータスの契約は `src/main.zig` の doc コメントが正である。

`-I <dir>` は、`import` が名指すライブラリのファイルの探索ルートを足す。作業ディレクトリが先頭で、`-I` の指定が書いた順に続く。ライブラリは、登録表に無ければ、ルートの配下の `foo/bar.sld`(`(foo bar)` の場合)から読まれる。`include` の名前は、それを書いたファイル(REPL では作業ディレクトリ)からの相対で、そのファイルのあるルートの外へは出られない。リンクは辿らない。環境変数は読まない。

Web UI は、アーカイブを展開したディレクトリで、Node.js を使って次を実行する。表示された `http://127.0.0.1:<ポート>/` をブラウザで開く。既定のポートは 8000 で、使用中のときは `node serve.mjs 8080` のようにポートを渡す。

```sh
node serve.mjs
```

`file://` で `index.html` を開いても、ブラウザが wasm を読ませないので動かない([ADR-0021](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/adr/0021-no-github-pages-defer-hosting.md))。Web UI にはファイルを開く手段が無いので、ライブラリの読み込みと `include` は、ファイルが無いと報告する。

## できること

v0.1.0 で動いたものに加えて、次が動く。

- 式の形: 可変個引数の `lambda`(`(lambda args ...)`、`(lambda (a . rest) ...)`)と、`define` の短縮形の同じ形。`parameterize`。`include` と `include-ci`(式の位置でも)。`cond-expand`(フィーチャ要件は識別子、`library`、`and`、`or`、`not`、`else`)。`features`。
- 制御: 完全な `call/cc`(`call-with-current-continuation`)。継続の多重起動と、`dynamic-wind` の巻き戻しと巻き戻し直しを含む。`values` と `call-with-values`。`apply`。
- 例外: `raise`、`raise-continuable`、`with-exception-handler`、`error`、`error-object?`、`error-object-message`、`error-object-irritants`、`read-error?`、`file-error?`。
- パラメータ: `make-parameter` と `parameterize`。
- 衛生的マクロ: `define-syntax`、`syntax-rules`(省略記号、ベクタのパターン、リテラル、`_`、省略記号のエスケープ `(... ...)`)、`let-syntax`、`letrec-syntax`、`syntax-error`。マクロを定義するマクロも動く。
- ライブラリ: `define-library`(`export`(`rename` を含む)、`import`、`begin`、`include`、`include-ci`、`include-library-declarations`、`cond-expand`)と、`import`(`only`、`except`、`prefix`、`rename`)。REPL でも `import` が使える。ライブラリは、登録済みのもの、REPL の中で定義したもの、探索ルートの下の `.sld` ファイルのものを読める。処理系が持つ唯一の組み込みのライブラリは `(sucheme core)` で、組み込みの手続きと特殊形式を持つ。
- `include-ci`: 対象のファイルを、識別子と文字名を畳み込んで読む(`#!fold-case` で始まるファイルとして読む)。文字リテラルと文字列は畳み込まない。
- 資源の限界: ヒープの上限に届くと、深い再帰も、1行の中のマクロの展開も、エラーで止まる。

## できないこと

このリリースでは、次は動かない。いずれも後の段階で入る([docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/roadmap.md))。

- `let`、`cond`、`case`、`and`、`or`、`when`、`unless`、`do`、`quasiquote`、`define-record-type`、`guard`、`define-values` などの派生構文。標準ライブラリの名前(`(scheme base)` など)での `import`。これらは段階3で入る。
- `eval`、`exit`、ポート、`display`、`write`、`newline` などの入出力の手続き、ファイルの入出力。ファイルの実行(`sucheme prog.scm`)。
- `append`、`reverse`、`map`、`for-each`、`list-ref`、`assoc`、`memq`、`cadr` などのリストの手続き。除算 `/`、`zero?`、`even?`、`odd?`、`abs`、`min`、`max`、`floor`、`expt`、`sqrt`、`number->string` などの数の手続き。`make-vector`、`vector-set!`、`set-car!` などの変更の手続き。`substring`、`string-append`、`string=?`、`char=?` などの文字列と文字の手続き。
- 浮動小数点数、多倍長整数、有理数、複素数。整数は固定長で、あふれるとエラーになる。ブロックコメント(`#|` から `|#`)、`#;`、データラベル、縦棒で囲んだ識別子、`#!fold-case` の指令は読めない。ASCII でない文字の識別子も読めない。
- REPL の行編集(カーソル移動、履歴、補完)。

次の既知の制限がある。いずれも結果は決めた形で返るもので、後の段階で直すかどうかを決める。

- 本体の先頭に置いた `begin`(定義を含むもの、空のもの)と、本体の先頭の `include` と `cond-expand` の中の定義は、定義の並びとして展開されない。`(lambda () (begin (define x 1)) x)` は、エラーになる。
- `let-syntax` と `letrec-syntax` の本体に `define` と `define-syntax` は置けない。
- マクロが導入した最上位の `define` と `define-syntax` は、衛生的でない。利用側の同じ綴りの最上位の変数を書き換える。
- 入れ子の `lambda` を重ねる止まらないマクロの展開は、時間で終わらないことがある。
- ライブラリの表と `import` の作業領域は、ヒープの上限に数えられない。巨大な入力では、上限より多いメモリを使いうる。ファイルは 1 MiB までで、これを超えると読まずに断る。
- パラメータの読み出しは、`parameterize` の入れ子の深さに比例して遅くなる。
- REPL で解決した名前ごとに、未束縛のセルが残る。

## 動作保証の範囲

- 実行して確かめた: x86_64 Linux の実行ファイルは、リリースの成果物そのもの(`ReleaseSafe`)を、組み立ての直後に実行して `--version` と階乗の計算を確かめている。テストは Linux x86_64 と Windows x86_64 で、プルリクエストの先頭と `main` への push のたびに、自動で走っている。
- ビルドだけ確かめた: Windows の実行ファイル、macOS(x86_64、aarch64)、Linux aarch64、Windows aarch64。リリースの成果物そのものは、これらの環境で実行して確かめていない。aarch64 の実行は、どこでも確かめていない([ADR-0033](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/adr/0033-aarch64-built-but-not-tested.md))。macOS は、署名も公証もしていない。
- Web UI: ブラウザ自動化のテストは無い。wasm のエクスポートを Node.js から呼ぶ往復テストだけが自動で走る。ブラウザ固有の問題は検出されない。
- 問題が見つかった場合は、issue で知らせてほしい。

## 暫定の値

GC を起動する閾値(割り当ての倍率と最小値)は暫定である。性能は測っておらず、遅い。ベンチマークは未実施で、準拠テストが通った後の性能の測定で見直す。ヒープの上限に届くと `heap limit exceeded` で止まる([ADR-0031](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/adr/0031-gc-at-machine-step-boundaries.md))。例外の送出のために予約する領域の大きさは 4 KiB で、再入の深さに比例する確保がそれで賄い切れない場合がある(受け入れた制約。[docs/design/runtime.md](https://github.com/suchi/sucheme-zig/blob/v0.2.0/docs/design/runtime.md) の送出のための予約領域)。
