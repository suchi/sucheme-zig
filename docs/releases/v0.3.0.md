# sucheme v0.3.0

sucheme-zig の3つ目のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階3(Scheme による標準ライブラリ)にあたる。派生構文とリストや文字列の手続きを Scheme で書いて実行ファイルに埋め込み、`(scheme base)` の骨格と、`(scheme case-lambda)`、`(scheme cxr)`、`(scheme lazy)` が入った。REPL とファイルの実行の初期環境は `(scheme base)` である。R7RS-small の準拠を名乗れる段階ではない。数値塔(段階4)とポートと入出力(段階5)は、まだ無い。どこまで動くかの正は [docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/roadmap.md) の「現在地」と、生成物の [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/status/conformance.md) である。ここには数を書き写さない。

このリリースは、リポジトリにアクセスできる人だけが取得できる(リポジトリは private である。[ADR-0020](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0020-repository-visibility-private.md))。ライセンスは付与していない(UNLICENSED、全権利保留。[ADR-0022](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0022-unlicensed-proprietary.md))。

## v0.2.0 からの取り消し

- `(sucheme core)` は、利用者のコードからは `import` できなくなった。v0.2.0 では、処理系が持つ唯一の組み込みのライブラリとして使えた。今は、実行ファイルに埋め込んだ標準ライブラリの中でだけ取り込め、REPL、ファイルのプログラム、利用者のライブラリからの `import` は `bad import: the library (sucheme core) is only for the standard libraries the executable carries` で断られる。代わりに `(scheme base)` などを使う。`%` で始まる内部の名前(`%make-record-type` など)も、利用者からは見えない([ADR-0037](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0037-core-library-exposed-in-stage-2.md) の追記、[ADR-0039](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0039-standard-environment-installed-at-init.md))。
- REPL の最初の環境が、`(sucheme core)` の束縛から、`(scheme base)` がエクスポートするものに替わった。`(scheme base)` に無い名前(`%` で始まる名前など)は、最初から見えない。

アーカイブの中の配置は v0.2.0 と同じである。実行ファイルのアーカイブは、`sucheme-v0.3.0-<ターゲット>/` というディレクトリを1つ含み、その下に実行ファイル(Windows は `sucheme.exe`)、`LICENSE`、第三者の表示 `THIRD-PARTY-NOTICES.txt` が入る。Web UI の zip は `sucheme-web-v0.3.0/` を1つ含む。標準ライブラリ(`lib/` の `.sld` と `.scm`)は実行ファイルと `sucheme.wasm` に埋め込んであり、別のファイルとしては配らない。実行ファイルは `ReleaseSafe` で作ってあり、strip していない。

## 取得の確認

ダウンロードしたファイルが壊れていないことは、`SHA256SUMS` と同じディレクトリで次を実行して確かめる。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v0.3.0-x86_64-linux-musl.tar.gz
./sucheme-v0.3.0-x86_64-linux-musl/sucheme --version      # sucheme 0.3.0
./sucheme-v0.3.0-x86_64-linux-musl/sucheme                # REPL
./sucheme-v0.3.0-x86_64-linux-musl/sucheme prog.scm       # ファイルのプログラムを実行する
./sucheme-v0.3.0-x86_64-linux-musl/sucheme -I lib prog.scm # ライブラリの探索ルートを足す
```

引数なしで起動すると、標準入力が尽きるまで REPL が動く。終えるには、標準入力を閉じる(Linux と macOS の端末では Ctrl-D)。`exit` は無い。

ファイル名を渡すと、そのファイルのプログラムを、REPL と同じ初期環境(`(scheme base)`)で先頭から評価する。式の値は出力しない(出力の手続き `display` などは段階5で入る)。終了ステータスは、最後まで実行すれば 0、実行時エラーで止まれば 1(stderr に `error: ` と説明を出す)、ファイルを読めなければ 66、ファイルの後ろに引数が続けば 64 である。展開時のエラーには、`prog.scm:2:3: ` のように、ファイルと行と桁を前置する。標準入力のプログラム(`-`)は未実装で、69 で終了する。コマンドラインと終了ステータスの契約は `src/main.zig` の doc コメントが正である。

`-I <dir>` と `include` の探索の規則は v0.2.0 と同じである。

Web UI は、アーカイブを展開したディレクトリで `node serve.mjs` を実行し、表示された `http://127.0.0.1:<ポート>/` をブラウザで開く。`file://` で開いても動かない([ADR-0021](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0021-no-github-pages-defer-hosting.md))。Web UI には、選んで実行できるサンプルが6個あり、入力したソースを URL のフラグメント(`#code=...`)に入れた共有リンクを作れる。リンクを開くとソースが復元されるが、自動では実行しない。

## できること

v0.2.0 で動いたものに加えて、次が動く。

- ライブラリ: `(scheme base)`(実装のある必須識別子だけをエクスポートする)、`(scheme case-lambda)`、`(scheme cxr)`、`(scheme lazy)`。REPL とファイルのプログラムの初期環境は `(scheme base)` で、`import` しなくても使える。
- 派生構文: `let`(名前つきを含む)、`let*`、`letrec`、`letrec*`、`cond`、`case`、`and`、`or`、`when`、`unless`、`do`、`quasiquote`(リーダの `` ` `` `,` `,@` の略記を含む)、`let-values`、`let*-values`、`define-values`、`define-record-type`、`guard`、`case-lambda`、`delay`、`delay-force`。
- 本体の定義: 本体の先頭の `begin`、`include`、`cond-expand` が持つ定義は、本体の定義の並びになる。`let-syntax` と `letrec-syntax` の本体に `define` と `define-syntax` を置ける(本体は自分の有効範囲を持ち、外側の並びには繋ぎ込まない)。
- 対とリスト: `set-car!`、`set-cdr!`、`append`、`reverse`、`list-tail`、`list-ref`、`list-set!`、`list-copy`、`make-list`、`memq`、`memv`、`member`、`assq`、`assv`、`assoc`、`map` と `for-each`(複数のリストを取る)、`caar` などの合成アクセサ、`boolean=?`。`equal?` は、循環したデータでも止まり、共有構造の比較は節点の数に比例する時間で終わる。
- 文字とシンボル: `char=?` などの比較、`symbol=?`、`symbol->string`、`string->symbol`。使われなくなったシンボルは回収される。
- 文字列: `make-string`、`string`、`string-set!`、`string-copy`、`string-copy!`、`string-fill!`、`substring`、`string-append`、`string=?` などの比較、`string->list`、`list->string`、`string->vector`、`vector->string`、`string-map`、`string-for-each`。
- ベクタとバイトベクタ: `make-vector`、`vector-set!`、`vector-fill!`、`vector-copy`、`vector-copy!`、`vector-append`、`vector->list`、`list->vector`、`vector-map`、`vector-for-each`。バイトベクタ(`#u8(...)` の読み書き)と、`bytevector-u8-ref` などの手続き、`utf8->string`、`string->utf8`。
- EOF の値と約束: `eof-object`、`eof-object?`、`make-promise`、`promise?`、`force`。
- リテラルは定数である。`quote` したデータ、自己評価するリテラル、`symbol->string` の結果に書き込む手続き(`set-car!`、`string-set!`、`vector-set!` など)は、`cannot modify a constant in <手続き名>` で断る。
- リーダ: ブロックコメント(`#|` から `|#`、入れ子にできる)、データのコメント `#;`、`#!fold-case` と `#!no-fold-case` の指令、縦棒で囲んだ識別子(`|a b|`)、データラベル(`#0=` と `#0#`)。
- 資源の限界: 展開時に作るスコープの入れ子は 10000 段までで、超えると `implementation restriction: scopes are nested more than 10000 deep` で止まる。入れ子の `lambda` や `let-syntax` を重ねて止まらないマクロも、これで止まる。コアの中間表現は GC ヒープにあり、失敗した展開の節点と、定義に失敗したライブラリの表と、コードが指さなくなった未束縛のセル(REPL で解決した未知の名前)は、GC が回収する。ライブラリの表と `import` の作業は、ヒープの上限に数える。

## できないこと

このリリースでは、次は動かない。いずれも後の段階で入る([docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/roadmap.md))。

- 浮動小数点数、多倍長整数、有理数、複素数の読み書きと演算。整数は固定長で、あふれるとエラーになる。`1.5` や `1/2` は読めない。除算 `/`、`exact`、`inexact`、`max`、`min`、`floor`、`expt`、`sqrt`、`number->string`、`string->number` など、数値塔を要る手続き。これらは段階4で入る。
- `eval`、`exit`、ポート、`display`、`write`、`newline` などの入出力の手続き、ファイルの入出力、プログラムへの引数、標準入力のプログラム。これらは段階5で入る。
- 大文字小文字を畳み込む文字列と文字の手続き(`string-upcase`、`char-upcase`、`string-ci=?` など)と `(scheme char)`。Unicode の表が入る段階4で入る。
- 循環したデータの印字。REPL が循環したデータを結果として印字しようとすると、止まらない。データラベルで循環したデータを作ることはできるが、印字はしないこと。段階5の `write` で直す。
- REPL の行編集(カーソル移動、履歴、補完)。

次の既知の制限がある。いずれも結果は決めた形で返るもので、後の段階で直すかどうかを決める。

- マクロが導入した最上位の `define` と `define-syntax` は、衛生的でない。利用側の同じ綴りの最上位の変数を書き換える。R7RS 4.3 は、最上位の変数の定義が束縛を導入するかを実装に委ねている。段階6の準拠検証で、直すかを決める。
- パラメータの読み出しは、`parameterize` の入れ子の深さに比例して遅くなる。段階6で見直す。
- ファイルを読むときのリーダの作業領域は、ヒープの上限に数えられない。ファイルは 1 MiB までで、これを超えると読まずに断る。段階5で直す。
- 多くの値を返す `values` は、個数に比例する領域を1ステップの中で確保する。段階6で直す。

## 動作保証の範囲

- 実行して確かめた: x86_64 Linux の実行ファイルは、リリースの成果物そのもの(`ReleaseSafe`)を、組み立ての直後に実行して `--version` と階乗の計算を確かめている。テストは Linux x86_64 で、プルリクエストへの push のたびに自動で走る。Windows x86_64 のテストと、規模を試すテストは、プルリクエストを ready にしたときに走る。
- ビルドだけ確かめた: Windows の実行ファイル、macOS(x86_64、aarch64)、Linux aarch64、Windows aarch64。リリースの成果物そのものは、これらの環境で実行して確かめていない。aarch64 の実行は、どこでも確かめていない([ADR-0033](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0033-aarch64-built-but-not-tested.md))。macOS は、署名も公証もしていない。
- Web UI: ブラウザ自動化のテストは無い。wasm のエクスポートを Node.js から呼ぶ往復テストと、サンプルの評価と共有リンクの符号化のテストだけが自動で走る。ブラウザ固有の問題は検出されない。
- 問題が見つかった場合は、issue で知らせてほしい。

## 暫定の値

GC を起動する閾値(割り当ての倍率と最小値)は暫定である。性能は測っておらず、遅い。起動のたびに `(scheme base)` を展開するので、空の入力でも数ミリ秒かかる。ベンチマークは未実施で、準拠テストが通った後の性能の測定で見直す。ヒープの上限に届くと `heap limit exceeded` で止まる([ADR-0031](https://github.com/suchi/sucheme-zig/blob/v0.3.0/docs/adr/0031-gc-at-machine-step-boundaries.md))。

## ビルドの情報

- Zig: 0.17.0([.zigversion](https://github.com/suchi/sucheme-zig/blob/v0.3.0/.zigversion))。
- 最適化: `ReleaseSafe`。パニックは安全検査で止まり、未定義動作にならない。
- 依存パッケージ: 無い(Zig の標準ライブラリのみ)。
- 第三者の表示: Zig と musl の表示を `THIRD-PARTY-NOTICES.txt` に入れている。
