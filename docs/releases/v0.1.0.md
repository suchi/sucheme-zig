# sucheme v0.1.0

sucheme-zig の最初のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階1(通しで動く最小の縦切り)にあたる。R7RS-small の準拠を名乗れる段階ではない。REPL で小さなプログラムを書いて動かせる、というところまでである。どこまで動くかの正は [docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/roadmap.md) の「現在地」と、生成物の [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/status/conformance.md) である。ここには数を書き写さない。

このリリースは、リポジトリにアクセスできる人だけが取得できる(リポジトリは private である。[ADR-0020](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/adr/0020-repository-visibility-private.md))。ライセンスは付与していない(UNLICENSED、全権利保留。[ADR-0022](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/adr/0022-unlicensed-proprietary.md))。

実行ファイルのアーカイブは、`sucheme-v0.1.0-<ターゲット>/` というディレクトリを1つ含み、その下に実行ファイル(Windows は `sucheme.exe`)、`LICENSE`、第三者の表示 `THIRD-PARTY-NOTICES.txt` が入る。Web UI の zip は `sucheme-web-v0.1.0/` を1つ含み、その下に `index.html`、スクリプト、`sucheme.wasm`、`serve.mjs`、スタイルシート、`LICENSE`、`THIRD-PARTY-NOTICES.txt` が入る。Windows の `.pdb` は含まない。実行ファイルは `ReleaseSafe` で作ってあり、strip していない。

## 取得の確認

ダウンロードしたファイルが壊れていないことは、`SHA256SUMS` と同じディレクトリで次を実行して確かめる。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v0.1.0-x86_64-linux-musl.tar.gz
./sucheme-v0.1.0-x86_64-linux-musl/sucheme --version     # sucheme 0.1.0
./sucheme-v0.1.0-x86_64-linux-musl/sucheme               # REPL
```

引数なしで起動すると、標準入力が尽きるまで REPL が動く。終えるには、標準入力を閉じる(Linux と macOS の端末では Ctrl-D)。`exit` は無い。プロンプトは `> `、閉じていない式の続きは `... ` である。エラーはその式の評価を終わらせるだけで、REPL は続く。ファイル名を渡しても、ファイルの実行は未実装だと伝えて終了する(終了ステータス 69)。コマンドラインと終了ステータスの契約は `src/main.zig` の doc コメントが正である。

Web UI は、アーカイブを展開したディレクトリで、Node.js を使って次を実行する。表示された `http://127.0.0.1:<ポート>/` をブラウザで開く。既定のポートは 8000 で、使用中のときは `node serve.mjs 8080` のようにポートを渡す。

```sh
node serve.mjs
```

`file://` で `index.html` を開いても、ブラウザが wasm を読ませないので動かない([ADR-0021](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/adr/0021-no-github-pages-defer-hosting.md))。

## できること

- 式: 数(固定長の整数)、真偽値、文字、文字列、ベクタ、シンボル、ペア、リスト、`quote`(`'`)、`if`、`lambda`、`define`(`(define (f x) ...)` の短縮形と内部 define を含む)、`set!`、`begin`。
- 手続き: 組み込みの手続きは小さな集合である。整数の算術と比較(`+` `-` `*` `quotient` `remainder` `modulo` `=` `<` など)、ペアとリスト(`cons` `car` `cdr` `list` `length` `null?` `pair?` など)、等価と型の述語(`eq?` `eqv?` `equal?` `not` `number?` `symbol?` `procedure?` など)、文字と文字列とベクタの参照(`char->integer` `string-length` `string-ref` `vector-length` `vector-ref` `vector` など)がある。手続きの名前の一覧は [docs/plans/0010-slices-1k-1l-primitives-and-repl-continuation.md](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/plans/0010-slices-1k-1l-primitives-and-repl-continuation.md) の 1k の一覧にある。R7RS の必須の識別子のうち束縛済みの数は [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/status/conformance.md) にある。
- 実行: 適切な末尾再帰。100万回の末尾再帰が一定のメモリで終わる。深い再帰は、上限に届くとエラーで止まる。
- GC: 非移動型の精密マーク・スイープ。ヒープの上限に届くと `heap limit exceeded` で止まる。
- REPL: 行コメント(`;`)、閉じていない式の継続行。

## できないこと

このリリースでは、次は動かない。いずれも後の段階で入る([docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/roadmap.md))。

- `let`、`cond`、`case`、`and`、`or`、`when`、`unless`、`do`、`quasiquote` などの派生構文。マクロ(`syntax-rules`)。
- `call/cc`、`dynamic-wind`、`values`、例外(`raise`、`with-exception-handler`、`error`)、`apply`、`eval`。
- `append`、`reverse`、`map`、`for-each`、`list-ref`、`assoc`、`memq`、`cadr` などのリストの手続き。除算 `/`、`zero?`、`even?`、`odd?`、`abs`、`min`、`max`、`floor`、`expt`、`sqrt`、`number->string` などの数の手続き。`make-vector`、`vector-set!`、`set-car!` などの変更の手続き。`substring`、`string-append`、`string=?`、`char=?` などの文字列と文字の手続き。`exit`。
- 浮動小数点数、多倍長整数、有理数、複素数。整数は固定長で、あふれるとエラーになる。`1.5` や `1/2` のような数は、読み取りでエラーになる。ブロックコメント(`#|` から `|#`)と `#;` も読めない。
- `display`、`write`、`newline` などの出力の手続き。ポート。ファイルの入出力。REPL は結果だけを表示する。
- ライブラリ(`define-library`、`import`)。`(scheme base)` などの標準ライブラリの名前での読み込み。
- ファイルの実行。コマンドラインの引数でプログラムを渡すことはできない。
- REPL の行編集(カーソル移動、履歴、補完)。標準入力の行を、そのまま読む。

## 動作保証の範囲

- 実行して確かめた: x86_64 Linux の実行ファイルは、リリースの成果物そのもの(`ReleaseSafe`)を、組み立ての直後に実行して `--version` と階乗の計算を確かめている。テストは Linux x86_64 と Windows x86_64 で、プルリクエストの先頭と `main` への push のたびに、自動で走っている。
- ビルドだけ確かめた: Windows の実行ファイル、macOS(x86_64、aarch64)、Linux aarch64、Windows aarch64。リリースの成果物そのものは、これらの環境で実行して確かめていない。aarch64 の実行は、どこでも確かめていない([ADR-0033](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/adr/0033-aarch64-built-but-not-tested.md))。macOS は、署名も公証もしていない。
- Web UI: ブラウザ自動化のテストは無い。wasm のエクスポートを Node.js から呼ぶ往復テストだけが自動で走る。ブラウザ固有の問題は検出されない。
- 問題が見つかった場合は、issue で知らせてほしい。

## 暫定の値

GC を起動する閾値(割り当ての倍率と最小値)は暫定である。性能は測っておらず、遅い。たとえば、100万回の末尾再帰は終わるが、数秒かかる環境がある。ベンチマークは未実施で、準拠テストが通った後の性能の測定で見直す。ヒープの上限に届くと `heap limit exceeded` で止まる([ADR-0031](https://github.com/suchi/sucheme-zig/blob/v0.1.0/docs/adr/0031-gc-at-machine-step-boundaries.md))。

## ビルドの情報

- Zig: 0.17.0([.zigversion](https://github.com/suchi/sucheme-zig/blob/v0.1.0/.zigversion))。
- 最適化: `ReleaseSafe`。パニックは安全検査で止まり、未定義動作にならない。
- 依存パッケージ: 無い(Zig の標準ライブラリのみ)。
- 第三者の表示: Zig と musl の表示を `THIRD-PARTY-NOTICES.txt` に入れている。
