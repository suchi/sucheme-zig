# sucheme v1.2.0

sucheme-zig の8つ目のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階8(Web UI の本格化)にあたる。計画は [docs/plans/0030-phase8-web-ui.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/plans/0030-phase8-web-ui.md) である。最終段階の完了を示すリリースである。ただし、段階7から外した項目(識別子の補完、継続行の差分読み取りなど)は、どの段階にも割り当てておらず、このリリースに入っていない。

ライセンスは MIT である([ADR-0050](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0050-relicense-under-mit.md))。この版の成果物の `LICENSE` は MIT の条文で、第三者のものの扱いも `LICENSE` の末尾に書いてある。

## v1.1.0 からの変更

Web UI が、公開のサイトで使えるようになり、対話と編集の補助が入った。実行ファイルでは、実行時のエラーに位置が付くようになった。

Web UI:

- 配置: <https://suchi.github.io/sucheme-zig/> で、インストールなしで使える。サイトは GitHub Pages で配られ、リリースの公開と手動の起動でだけ更新される([ADR-0056](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0056-deploy-web-ui-to-github-pages.md))。開発中の変更は、すぐには載らない。載っている版は、画面のタイトルの横に出る。
- 出力とエラーの分離: エラーの説明は、出力欄の下の別の欄に出る。エラーの前の出力は残る。`exit` は終了コード付きで、エラーとは別の色で知らせる。
- 停止: 評価は歩数ごとに区切って進むので、長い評価の間も画面は応答する。「Stop」ボタンか `Esc` で、いま走っている評価だけを止められ、それまでの定義は残る。評価中は経過時間が出る。
- `read` による対話: `(read)`、`(read-line)`、`(read-char)` などが入力を待つと、評価がそこで止まり、画面に1行の入力欄が出る。「End of input」(または Ctrl+D)で、ファイルの終わりを渡せる。
- エラー位置: 実行時のエラーの `行:桁:` を、入力欄の中の、誤りを起こした呼び出しの強調(色と波線の下線)で示す。
- 編集の補助: 入力欄で、括弧の対応の強調、Tab による字下げ(Shift+Tab で取る)、実行した入力の履歴(上下矢印)が使える。
- サンプル: 6個から11個に増えた(数値塔、文字列、文字列ポート、`dynamic-wind`、ライブラリを足した)。

実行ファイルとライブラリ:

- 実行時のエラーに、手続きの呼び出しの位置が付く(`行:桁: 説明`。ファイルのプログラムでは `ファイル名:行:桁: 説明`)。ネイティブの REPL とファイルの実行にも効く。位置が付くのは、手続きの呼び出しが送出した誤りだけである(下の「既知の制限」)。このため、誤りの文面の形が変わる。診断の文面を読む道具を作っている場合は、注意してほしい。
- 機械が、予算つきで歩数を進め、途中で止めて再開できるようになった([ADR-0053](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0053-resumable-machine-step-budget.md))。読み取りが入力待ちを返し、同じ呼び出しをやり直す([ADR-0055](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0055-input-wait-by-retrying-the-call.md))。歩数を分けて進めても、一度に進めた結果と同じになることを、テストで固定した(予算 1、3、50 歩ごとの実行と `run` の結果の一致。ストレスモードで、停止のたびに GC する)。
- 呼び出しの節点が位置を持つので、節点とセルのヒープ上の大きさが増えた([ADR-0054](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0054-call-node-source-spots.md))。ヒープの上限には、増えた分も数えられる。標準環境の読み込み後に保持するバイト数は、約2.7%増えた(8g-1 の PR での測定。531452 から 545836 バイト)。

利用者向けの文書は、Web UI の対話、停止、エラー位置、配置と、まだ無い機能の一覧を、実装に合わせて直した([docs/manual/guide/06-web-ui.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/manual/guide/06-web-ui.md)、[07-limitations.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/manual/guide/07-limitations.md)、[unimplemented.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/manual/reference/unimplemented.md))。

## 取得の確認

`SHA256SUMS` と同じディレクトリで、次を実行する。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v1.2.0-x86_64-linux-musl.tar.gz
./sucheme-v1.2.0-x86_64-linux-musl/sucheme --version    # sucheme 1.2.0
./sucheme-v1.2.0-x86_64-linux-musl/sucheme              # REPL
./sucheme-v1.2.0-x86_64-linux-musl/sucheme prog.scm     # ファイルのプログラムを実行する
```

REPL とファイルの最初の環境は `(scheme base)` である。`display` は `(scheme write)` にあるので、使う前に `(import (scheme write))` を実行する。REPL は、端末で何も打っていない状態の Ctrl-D、または `(import (scheme process-context))` のあとの `(exit)` で終える。そのほかの使い方は [v1.0.0](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/releases/v1.0.0.md) のリリースノートと同じである。

Web UI は、公開のサイトを開くか、`sucheme-web-v1.2.0.zip` を展開したディレクトリで `node serve.mjs` を実行して、表示された `http://127.0.0.1:<ポート>/` をブラウザで開く(Node.js が要る。`file://` で開いても動かない)。使い方は [docs/manual/guide/06-web-ui.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/manual/guide/06-web-ui.md) にある。

## WebAssembly の大きさ

許容基準([計画書 0030](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/plans/0030-phase8-web-ui.md) の決定4)は、配信される `sucheme.wasm` の gzip の転送量で 2 MiB(2097152 バイト)を上限とする仮の値である。リリースの準備の測定は、次のとおりである(2026-11-23)。

| 測定 | 生のバイト数 | gzip のバイト数 |
| --- | --- | --- |
| 公開のサイト(`1.2.0-dev` の版。`main` のコミット `b65b484` から配置したもの)に、`Accept-Encoding: gzip` で要求して受け取った本文 | 4507612 | 1375972 |
| この版(`1.2.0`)のコミットから `zig build wasm`(`ReleaseSafe`)で作った成果物を、`gzip -9` で圧縮 | 4507475 | 1361056 |

どちらも上限の 2097152 バイトの内にあり、公開のサイトの値は、上限の約66%である。2つの値の差(生で 137 バイト、gzip で 14916 バイト)の原因は、確かめていない。推測として、(1) 測った木が違う(公開のサイトは `b65b484`、ローカルは、その後に入った文書の変更と、版の文字列の変更を含む)、(2) 圧縮の器が違う(GitHub Pages の gzip の水準は分からず、ローカルは `-9` である。`-6` では 1366461 バイトだった)。生の差が小さいことから、gzip の差の大半は(2)による、と見ている(これも推測)。Unicode の表が、この大きさのうちどれだけを占めるかは、測っていない。

## 既知の制限

このリリースで受け入れた制限である。直すかどうかは、[docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/roadmap.md) と [docs/design/open-questions.md](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/design/open-questions.md) が正である。

Web UI:

- 動作を確かめたブラウザは Chromium だけである。他のブラウザは確かめていない。ブラウザの自動テストは無く(計画書 0030 の決定8)、画面の操作は、下の「動作保証の範囲」の範囲だけを手で確かめた。自動で走るのは、WebAssembly のエクスポートと、`web/` の DOM に触れない関数を Node.js から試すテストだけである。
- 「Stop」が効くのは、歩数の区切りである。`import` で読み込むライブラリの本体と、1歩の中で長く走る組み込みの手続き(巨大なベクタの作成など)は、終わるまで止まらない。3秒たっても応えないときは、処理系を作り直し、それまでの定義は失われる。3秒での作り直しは、ブラウザでは確かめていない。
- エラー位置の強調は、前の実行で定義した手続きの中で起きた誤りでは、前の入力の位置が付くので、いまの入力の別の場所を指すことがある(Web UI の入力がファイル名を持たないため)。出力と説明の境目は `error: ` の文字列で探すので、プログラムの出力や `error` に渡した文字列がこれを含むと、位置を誤る、または強調が出ないことがある。
- 入力待ちの欄で渡せるのは1行である。日本語などの入力の変換を確定する `Enter` では、送信しない作りにしているが、実際の変換での動作は確かめていない。
- 公開のサイトの更新は、リリースの公開と手動の起動だけである。リリースの公開の起動(`release: published`)が、環境 `github-pages` の保護規則に許されるかは、このノートの時点で確かめていない。許されなかったときは、手動の起動で配置する([ADR-0056](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/adr/0056-deploy-web-ui-to-github-pages.md))。

実行時のエラーの位置:

- 位置が付くのは、手続きの呼び出しが送出した誤りだけである。未束縛の変数の参照のような、呼び出しでない式の誤り、標準ライブラリの手続きの中の誤り、マクロの出力の呼び出しの誤りには、位置が付かない([設計](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/design/frontend.md)の「実行時の誤りの位置」)。

REPL の行編集と実行ファイル(v1.1.0 から変わらない):

- 識別子の補完(Tab)は無い。継続行の差分読み取りが無く、閉じ忘れの式を含む、上限(64 KiB)に近い入力を貼ると、費用が入力の大きさの2乗に比例する。
- Windows のコンソールの行編集は、実機で一部だけ確かめた。macOS の実機での動作も確かめていない。文字幅は仮の実装で、全角の文字、結合文字、絵文字を含む行は、カーソルの位置がずれる。
- 評価の間の Ctrl-C は、sucheme を終え、それまでの定義は失われる。評価だけを止める手段は、実行ファイルの REPL には無い(Web UI の「Stop」とは別である)。
- 入力が端末の高さを超える長さになると、再描画のたびに、画面の外へ出た行が重複して残る。複数行の貼り付けは描画に時間がかかる。履歴のファイルは、足すだけで縮まず、複数の sucheme が同時に書くと、行が消えることがある。

これらの詳細は [v1.1.0 のリリースノート](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/releases/v1.1.0.md)の「既知の制限」にある。標準入力のプログラム(`sucheme -`)が無いこと、マクロが導入したトップレベルの定義が衛生的でないこと、性能とメモリの項目は、[v1.0.0 のリリースノート](https://github.com/suchi/sucheme-zig/blob/v1.2.0/docs/releases/v1.0.0.md)の「既知の制限」にあり、そのまま残っている。

## 動作保証の範囲

- 実行して確かめた: Linux x86_64 の成果物を、`--version` と簡単な式の評価で確かめる。テストは Linux x86_64 で自動で走る。Windows x86_64 のテストは、層2 で走る。
- ビルドだけ確かめた: Windows、macOS、Linux aarch64、Windows aarch64 の実行ファイルのうち、上で実行して確かめたもの以外。macOS は署名も公証もしていない。
- Web UI: Chromium で、公開のサイトとローカルの配信に対し、ページの全サンプル(11個)を実行して確かめた。入力待ちの操作とエラー位置の強調は、Chromium(Playwright)での実機の操作で確かめた。停止の表示、Worker の作り直し、編集の補助(括弧の強調、Tab、履歴)の画面の見え方と操作は、ブラウザで確かめていない。これらの関数と Worker の経路は、Node.js からの自動テストで試している。
- 問題が見つかった場合は、issue で知らせてほしい。
