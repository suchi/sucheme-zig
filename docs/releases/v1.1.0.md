# sucheme v1.1.0

sucheme-zig の7つ目のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階7(REPL の編集機能)にあたる。REPL に行編集が入った。段階7の範囲は、識別子の補完と差分読み取りを外す形に改めた([ADR-0051](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/adr/0051-narrow-stage-7-and-release-v1-1-0.md))。この2つは、このリリースに入っていない。

このリリースは、リポジトリにアクセスできる人だけが取得できる(リポジトリは private である。[ADR-0020](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/adr/0020-repository-visibility-private.md))。ライセンスは MIT である([ADR-0050](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/adr/0050-relicense-under-mit.md))。この版の成果物の `LICENSE` は MIT の条文で、第三者のものの扱いも `LICENSE` の末尾に書いてある。`v1.0.0` と `v1.1.0-pre.1` の成果物は、UNLICENSED の `LICENSE` を持ち、MIT ではない。

## v1.1.0-pre.2 からの変更

先行版 `v1.1.0-pre.2` との間に、実行ファイルの挙動の変更は無い。版の表示が `1.1.0` になり、利用者向けの文書を実装に合わせて直した。

- `docs/manual/guide/03-repl.md` の、Windows の行編集、括弧の対応の表示、履歴の保存の記述を、実装に合わせた。履歴の保存先と形式、括弧の対応の表示の規則、実機での確認の範囲を書いた。
- `docs/manual/guide/07-limitations.md` と `docs/manual/reference/unimplemented.md` の、行編集についての記述を直した。

## v1.0.0 からの変更

REPL の行編集が入った。標準入力と標準出力の両方が端末のときだけ働き、パイプとファイルの入力は、これまでどおり1行ずつ読む。

- Emacs 風のキー割り当て(カーソル移動、語単位の移動、切り取りと貼り付け、取り消し)で、打っている行を編集できる。
- 履歴を、上下の矢印と Ctrl-R(後ろ向きの増分検索)で呼び出せる。履歴は、環境変数 `SUCHEME_HISTORY` のパス(無ければホームの下の `.sucheme_history`)のファイルに保存し、次の起動で読む。
- 閉じていない式は継続行になり、前の行へ戻って直せる(複数行の編集)。
- カーソルの位置と対になる括弧を、反転表示で示す。
- Windows のコンソールでも、行編集が働く。
- ライセンスを、UNLICENSED から MIT に変えた。

キー割り当ての一覧と注意は、[docs/manual/guide/03-repl.md](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/manual/guide/03-repl.md) にある。

## 取得の確認

`SHA256SUMS` と同じディレクトリで、次を実行する。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v1.1.0-x86_64-linux-musl.tar.gz
./sucheme-v1.1.0-x86_64-linux-musl/sucheme --version    # sucheme 1.1.0
./sucheme-v1.1.0-x86_64-linux-musl/sucheme              # REPL
./sucheme-v1.1.0-x86_64-linux-musl/sucheme prog.scm     # ファイルのプログラムを実行する
```

REPL とファイルの最初の環境は `(scheme base)` である。`display` は `(scheme write)` にあるので、使う前に `(import (scheme write))` を実行する。REPL は、端末で何も打っていない状態の Ctrl-D、または `(import (scheme process-context))` のあとの `(exit)` で終える。そのほかの使い方は [v1.0.0](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/releases/v1.0.0.md) のリリースノートと同じである。

## 既知の制限

このリリースで受け入れた制限である。直すかどうかは、[docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/roadmap.md) の「段階7の後続の作業」と、[docs/design/open-questions.md](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/design/open-questions.md) が正である。

REPL の行編集:

- 識別子の補完(Tab)は無い。Tab は文字として入る。
- 継続行の差分読み取りが無い。REPL は、継続のたびに、溜めた入力の全体を読み直す。そのため、閉じ忘れの式を含み、正しい式を多数並べた、上限(64 KiB)に近い入力を貼ると、費用が溜めた入力の大きさの2乗に比例し、待たされる。結果は正しい。この制約は v1.0.0 から続いている。
- Windows のコンソールの行編集は、実機で一部だけ確かめた。複数行の編集、履歴、Emacs 風のキーは、動くことを確かめた。終了時の端末のモードの復元、日本語の入力と表示、旧来のコンソール(レガシーのコンソール)での見え方は、確かめていない。崩れたときは、パイプで入力すると、行編集のない読み方に切り替わる。macOS の実機での動作も確かめていない。
- 文字幅は仮の実装で、全角の文字、結合文字、絵文字を含む行は、カーソルの位置がずれる([ADR-0049](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/adr/0049-line-editor-in-zig-minimal-core-first.md))。
- 評価の間の Ctrl-C は、sucheme を終え、それまでの定義は失われる。評価だけを止める手段は無い。
- 入力が端末の高さを超える長さになると、再描画のたびに、画面の外へ出た行が重複して残る。複数行の貼り付けは、1文字ごとに全体を描き直すので、長い式を貼ると、描画に時間がかかる。
- 履歴のファイルは、足すだけで縮まない。複数の sucheme を同時に起動して同じファイルに書くと、片方の行が上書きされて消えることがある。

v1.0.0 の既知の制限のうち、行編集に関するもの以外は、そのまま残っている。実行時のエラーに位置が付かないこと、標準入力のプログラム(`sucheme -`)が無いこと、マクロが導入したトップレベルの定義が衛生的でないこと、性能とメモリの項目は、[v1.0.0 のリリースノート](https://github.com/suchi/sucheme-zig/blob/v1.1.0/docs/releases/v1.0.0.md)の「既知の制限」にある。

## 動作保証の範囲

- 実行して確かめた: Linux x86_64 の成果物を、`--version` と簡単な式の評価で確かめる。テストは Linux x86_64 で自動で走る。Windows x86_64 のテストは、層2 で走る。行編集は、Linux の疑似端末と、Windows のコンソール(上の既知の制限に書いた範囲)で確かめた。
- ビルドだけ確かめた: Windows、macOS、Linux aarch64、Windows aarch64 の実行ファイルのうち、上で実行して確かめたもの以外。macOS は署名も公証もしていない。
- Web UI: v1.0.0 と同じで、ブラウザ自動化のテストは無い。
- 問題が見つかった場合は、issue で知らせてほしい。
