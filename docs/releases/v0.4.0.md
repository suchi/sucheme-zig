# sucheme v0.4.0

sucheme-zig の4つ目のリリースである。Zig で作る R7RS-small 準拠の Scheme インタプリタの、段階4(数値塔と Unicode)にあたる。多倍長整数、有理数、浮動小数点数、複素数と、`(scheme inexact)`、`(scheme complex)`、`(scheme char)` が入り、リーダが ASCII でない文字の識別子を読むようになった。並行して進めた段階5(ポートと入出力)の大部分も含む。ポート、`display` と `write`、ファイルの入出力、`read`、`eval`、`load`、`exit`、`(scheme r5rs)` などで、R7RS 付録Aのライブラリはすべて `import` できる。段階5は完了していない(下の「できないこと」)。R7RS-small の準拠を名乗れる段階ではない。どこまで動くかの正は [docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/roadmap.md) の「現在地」と、生成物の [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/status/conformance.md) である。ここには数を書き写さない。

このリリースは、リポジトリにアクセスできる人だけが取得できる(リポジトリは private である。[ADR-0020](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/adr/0020-repository-visibility-private.md))。ライセンスは付与していない(UNLICENSED、全権利保留。[ADR-0022](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/adr/0022-unlicensed-proprietary.md))。

## v0.3.0 からの変更

v0.3.0 で誤りになったもののうち、次は誤りにならなくなった。

- 整数があふれなくなった。固定長を超える整数は、多倍長整数になる。v0.3.0 では誤りだった。
- ファイルの名前の後ろに引数を続けると、v0.3.0 は 64 で終了した。今は、その引数をプログラムに渡して実行する(`(command-line)` で読める)。
- `1.5`、`1/2`、`#x1F`、`1e10`、`+inf.0`、`1+2i` など、数の綴りを読む。v0.3.0 では読めなかった。

## 取得の確認

ダウンロードしたファイルが壊れていないことは、`SHA256SUMS` と同じディレクトリで次を実行して確かめる。

```sh
sha256sum -c SHA256SUMS
```

`SHA256SUMS` は成果物と同じ場所から配るので、破損や取り違えには効くが、改ざんには効かない。署名と attestation は行っていない([ADR-0034](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/adr/0034-release-shape.md))。

## 使い方

```sh
tar xzf sucheme-v0.4.0-x86_64-linux-musl.tar.gz
./sucheme-v0.4.0-x86_64-linux-musl/sucheme --version         # sucheme 0.4.0
./sucheme-v0.4.0-x86_64-linux-musl/sucheme                   # REPL
./sucheme-v0.4.0-x86_64-linux-musl/sucheme prog.scm a b      # ファイルのプログラムを、引数 a b を渡して実行する
./sucheme-v0.4.0-x86_64-linux-musl/sucheme -I lib prog.scm   # ライブラリの探索ルートを足す
```

引数なしで起動すると、標準入力が尽きるまで REPL が動く。終えるには、標準入力を閉じる(Linux と macOS の端末では Ctrl-D)か、`(import (scheme process-context))` のあとで `(exit)` を呼ぶ。

REPL とファイルのプログラムの最初の環境は、v0.3.0 と同じく `(scheme base)` である。`display` と `write` は `(scheme write)`、`sqrt` や `exp` は `(scheme inexact)`、`exit` と `command-line` は `(scheme process-context)` にあるので、使う前に `import` する。

```scheme
(import (scheme base) (scheme write))
(display (/ 1 3)) (newline)     ; 1/3
(write (expt 2 100)) (newline)  ; 1267650600228229401496703205376
```

ファイル名を渡すと、そのファイルのプログラムを先頭から評価する。式の値は出力せず、プログラムが現在の出力ポートに書いたもの(`display`、`write-string` など)が標準出力に出る。プログラムの `read` や `read-char` は標準入力から読む。終了ステータスは、最後まで実行すれば 0、実行時エラーで止まれば 1(stderr に `error: ` と説明を出す)、ファイルを読めなければ 66、プログラムが `exit` を呼べばその引数から決まる値である。標準入力のプログラム(`-`)は未実装で、69 で終了する。コマンドラインと終了ステータスの契約は `src/main.zig` の doc コメントが正である。

`-I <dir>` と `include` の探索の規則は v0.3.0 と同じである。`load` も、同じ探索ルートの規則でファイルを開く(名前は、いつも作業ディレクトリを基準にする)。プログラムが開くファイル(`open-input-file` など)は、探索ルートに制約されない。

Web UI は、アーカイブを展開したディレクトリで `node serve.mjs` を実行し、表示された `http://127.0.0.1:<ポート>/` をブラウザで開く。`file://` で開いても動かない([ADR-0021](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/adr/0021-no-github-pages-defer-hosting.md))。Web UI には、選んで実行できるサンプルが6個あり、入力したソースを URL のフラグメント(`#code=...`)に入れた共有リンクを作れる。Web UI では、`display` などの出力は結果と同じ欄に出る。ファイルは開けず(`file-error` になる)、標準入力は最初から終わりにある。

## できること

v0.3.0 で動いたものに加えて、次が動く。

段階4(数値塔と Unicode):

- 数: 固定長の整数、多倍長整数、有理数、浮動小数点数(IEEE 754 の倍精度)、複素数(直交形式。各部は正確でも不正確でもよい)。`features` は `exact-closed`、`exact-complex`、`ratios`、`ieee-float` を返す。
- 数の読み書き: 基数の接頭辞(`#b` `#o` `#d` `#x`)、正確性の接頭辞(`#e` `#i`)、分数、小数、指数、`+inf.0` `-inf.0` `+nan.0`、直交形式と極形式の複素数。浮動小数点数は、読み直すと同じ値になる最短の桁で書く。`number->string` と `string->number` は基数 2、8、10、16 を扱う。
- 数の手続き: 四則と比較、`exact` と `inexact`、`floor` 系と整数除算の全組、`numerator`、`denominator`、`rationalize`、`exact-integer-sqrt`、`expt`、`max`、`min` など。`eqv?` と `equal?` は、多倍長整数、有理数、複素数を値で比べる。
- `(scheme inexact)`: `exp`、`log`(底を取る2引数を含む)、`sin`、`cos`、`tan`、`asin`、`acos`、`atan`、`sqrt`、`finite?`、`infinite?`、`nan?`。複素数の引数と、定義域の外の実数(`(sqrt -4)` は `+2i`)も扱う。
- `(scheme complex)`: `make-rectangular`、`make-polar`、`real-part`、`imag-part`、`magnitude`、`angle`。
- `(scheme char)`: 文字の属性(`char-alphabetic?` など)、`digit-value`、`char-upcase` などの変換、`char-ci=?` などの比較、`string-upcase`、`string-downcase`、`string-foldcase`、`string-ci=?` などの比較。Unicode 18.0.0 の表による。`string-upcase` は、1文字が複数の文字になる変換(`ß` が `SS`)も行う。`features` は `full-unicode` を返す。
- リーダは、ASCII でない文字を含む識別子(`λ` など)を読む。`#!fold-case` は、Unicode の単純な畳み込みで識別子を畳み込む。

段階5(ポートと入出力)のうち、このリリースに入ったもの:

- ポート: 文字列ポート、バイトベクタポート、ファイルポート(`(scheme file)`)、コンソールのポート。`current-input-port`、`current-output-port`、`current-error-port` は `parameterize` で差し替えられる。`read-char`、`peek-char`、`read-line`、`read-string`、`read-u8`、`write-char`、`write-string`、`write-u8` などと、`call-with-port`、`with-output-to-file` などの手続き。
- `(scheme write)`: `display`、`write`、`write-shared`、`write-simple`。`write` は、循環したデータをデータラベル(`#0=` と `#0#`)つきで書き、止まる。REPL の結果の印字も、循環したデータで止まる。
- `(scheme read)`: `read`。読めない入力では `read-error?` が真になる条件を送出する。`#!fold-case` はポートごとに効く。
- `(scheme eval)` と `(scheme repl)`: `eval`、`environment`、`interaction-environment`。
- `(scheme load)`: `load`。ファイルの形式を1つずつ展開して走らせ、前の形式の定義とマクロが次の形式に効く。
- `(scheme process-context)`: `exit`(`dynamic-wind` の `after` を呼んでから終わる)、`emergency-exit`、`command-line`、`get-environment-variable`、`get-environment-variables`。
- `(scheme time)`: `current-second`、`current-jiffy`、`jiffies-per-second`。
- `(scheme r5rs)`: R5RS の識別子と、`exact->inexact`、`inexact->exact`、`scheme-report-environment`、`null-environment`。
- 展開時のエラーには、ライブラリのファイルと、`include` が読むファイルの中でも、`prog.scm:2:3: ` のようにファイルと行と桁を前置する。

## できないこと

このリリースでは、次は動かない。いずれも後の段階で入る([docs/roadmap.md](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/roadmap.md))。

- `current-error-port` への書き込みは、標準出力に出る。標準エラーに分けるのは段階5の残りで入る。
- 実行時のエラー(展開のあとのエラー)には、位置が付かない。`load` が読み込んだ形式の展開のエラーにも、位置は付かない。
- 標準入力のプログラム(`-`)。
- REPL の行編集(カーソル移動、履歴、補完)。

次の既知の制限がある。いずれも結果は決めた形で返るもので、後の段階で直すかどうかを決める。

- `environment`、`scheme-report-environment`、`null-environment` を繰り返し呼ぶと、常駐のメモリが伸び、ヒープの上限に届いても `heap limit exceeded` にならない。段階5の後で直す。
- 数の綴りの大きさに上限がある。桁は 100,000 個まで、指数の絶対値は 1,000,000 までで、超えると数として読まない(`unreadable token`)。上限の内側でも、`#e1e1000000` のような綴りは1つ読むのに時間がかかる。多倍長整数の演算そのものには、時間の上限が無い。
- 複素数の初等関数と2引数の `log` は、最後の桁が1だけずれることがある。符号つきの0の扱いは、C99 の複素数の関数と違うことがある。各部が倍精度の範囲の端に近い複素数では、`asin` などが有限の答えを失うことがある。
- `#!fold-case` の畳み込みは単純な畳み込みで、`ß` のように完全な畳み込みでだけ変わる文字は畳み込まない。
- `write` は、ASCII でない文字を含むシンボルを縦棒で囲んで書く(`(write 'λ)` は `|λ|`)。読み戻すと同じシンボルになる。
- REPL で、`#!fold-case` を書いた行のあとの行には、畳み込みが引き継がれない。同じ行の中では効く。
- 準拠スイートには、まだ落ちる項目がある(件数と内訳は [docs/status/conformance.md](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/status/conformance.md))。
- マクロが導入したトップレベルの `define` と `define-syntax` は、衛生的でない。利用側の同じ綴りのトップレベルの変数を書き換える。R7RS 4.3 は、トップレベルの変数の定義が束縛を導入するかを実装に委ねている。段階6の準拠検証で、直すかを決める。
- パラメータの読み出しは、`parameterize` の入れ子の深さに比例して遅くなる。段階6で見直す。
- ファイルを読むときのリーダの作業領域は、ヒープの上限に数えられない。ファイルは 1 MiB までで、これを超えると読まずに断る。
- 多くの値を返す `values` は、個数に比例する領域を1ステップの中で確保する。段階6で直す。

## 動作保証の範囲

- 実行して確かめた: x86_64 Linux の実行ファイルは、リリースの成果物そのもの(`ReleaseSafe`)を、組み立ての直後に実行して `--version` と階乗の計算を確かめている。テストは Linux x86_64 で、プルリクエストへの push のたびに自動で走る。Windows x86_64 のテストと、規模を試すテスト(浮動小数点数の無作為な値のラウンドトリップを含む)は、プルリクエストを ready にしたときに走る。
- ビルドだけ確かめた: Windows の実行ファイル、macOS(x86_64、aarch64)、Linux aarch64、Windows aarch64。リリースの成果物そのものは、これらの環境で実行して確かめていない。aarch64 の実行は、どこでも確かめていない([ADR-0033](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/adr/0033-aarch64-built-but-not-tested.md))。macOS は、署名も公証もしていない。
- Web UI: ブラウザ自動化のテストは無い。wasm のエクスポートを Node.js から呼ぶラウンドトリップのテストと、サンプルの評価と共有リンクの符号化のテストだけが自動で走る。ブラウザ固有の問題は検出されない。
- 問題が見つかった場合は、issue で知らせてほしい。

## 暫定の値

GC を起動する閾値(割り当ての倍率と最小値)は暫定である。性能は測っておらず、遅い。起動のたびに `(scheme base)` を展開するので、空の入力でも数ミリ秒かかる。ベンチマークは未実施で、準拠テストが通った後の性能の測定で見直す。ヒープの上限に届くと `heap limit exceeded` で止まる([ADR-0031](https://github.com/suchi/sucheme-zig/blob/v0.4.0/docs/adr/0031-gc-at-machine-step-boundaries.md))。

## ビルドの情報

- Zig: 0.17.0([.zigversion](https://github.com/suchi/sucheme-zig/blob/v0.4.0/.zigversion))。
- 最適化: `ReleaseSafe`。パニックは安全検査で止まり、未定義動作にならない。
- 依存パッケージ: 無い(Zig の標準ライブラリのみ)。
- Unicode の表: UCD 18.0.0 から生成した([tools/unicode-gen/ucd/SOURCE.md](https://github.com/suchi/sucheme-zig/blob/v0.4.0/tools/unicode-gen/ucd/SOURCE.md))。
- 第三者の表示: Zig と musl の表示に、Unicode の表のもとになった UCD の表示(Unicode License V3)を加えて、`THIRD-PARTY-NOTICES.txt` に入れている。v0.3.0 までの成果物には、Unicode の表は入っていない。
