# ADR-0043: 定義の途中のライブラリの表は、未束縛のセルを強く持つ

- ステータス: 採用
- 日付: 2026-10-21
- 一部置き換え: [ADR-0040: core-ir-in-the-gc-heap](0040-core-ir-in-the-gc-heap.md) の決定6のうち、定義の途中のライブラリの表にあたる部分を置き換える。REPL の表と、定義を終えたライブラリの表が、未束縛のセルを弱く持つことは変わらない

スライス 3o-5([plans/0023-slice-3o-ir-to-gc-heap.md](../plans/0023-slice-3o-ir-to-gc-heap.md))の実装の中で見つかった相互作用に対する判断である。

## 背景

ADR-0040 の決定6は、最上位の表(REPL とライブラリ)が自分の未束縛のセルを弱く持ち、GC がマークの後、掃除の前に、マークされなかった未束縛のセルの束縛を表から外す、とした。

ライブラリの本体の終わりの未束縛の検査(`src/syntax/library.zig` の `unboundNames`)は、表に残る値の無いセルから、未束縛の名前を報告する。本体の処理は、形式ごとに展開して機械で走らせ、その間に GC が走る。死んだコードだけが参照した名前(`(begin (if #f car-typo))` の `car-typo`)のセルは、どのコードからも指されなくなる。弱く持つと、本体の終わりまでに GC が走ればセルが外れて報告されず、走らなければ報告される。結果が GC の時期(ストレスモードか、ヒープの使い方)に依存する。ADR-0040 と計画書 0023 は、この相互作用に触れていなかった。

## 決定

定義の途中(状態 `loading`)のライブラリの表は、未束縛のセルを強く持つ。`library.Registry.begin` が表の `keep_unbound` を立て、`finish` が本体の終わりの検査を済ませてから下ろす。定義を終えた表は、REPL の表と同じく弱く持つ。定義に失敗したライブラリの表は、ADR-0040 の決定5のとおり中身を手放す。

検討した選択肢:

- 計画どおり、定義の途中の表も弱く持つ案。未束縛の検査の結果が GC の時期に依存する。
- ライブラリの表は、定義を終えたあとも強く持ち、REPL の表だけを弱く持つ案。定義を終えたライブラリの表にも、エクスポートしたマクロの展開が未束縛のセルを作ることがあり、それが残る。

## 結果

- メリット: 未束縛の検査は、今までどおり GC の時期に依存しない。REPL と定義を終えたライブラリの未束縛のセルは、コードが指していなければ回収される。
- デメリット・受け入れたトレードオフ: 1つのライブラリの本体が死んだコードで多くの未知の名前を参照すると、そのセルは本体の終わりまで残る。本体の終わりに未束縛として報告されて定義は失敗し、表は手放される。
- 将来の見直し条件: 未束縛の検査を、表に残るセルでなく別の記録(本体が参照した名前の一覧など)で行う設計に変えるとき。
