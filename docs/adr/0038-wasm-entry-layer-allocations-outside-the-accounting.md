# ADR-0038: WASM の入口層が確保する、計上の外のものを、エントリ層の例外として認める

- ステータス: 採用
- 日付: 2026-10-15

## 背景

[architecture.md](../design/architecture.md) の「確保点の一元化」は、ヒープの上限(`heap_limit_bytes`)に計上する確保を `heap.zig` に集める。エントリ層(`main.zig` と `wasm.zig`)の例外は、起動と終了に必要な、計上の対象でないものに限るとしている。[runtime.md](../design/runtime.md) の計上の対象の表は、WASM の出力バッファとホストの入力領域を、計上の対象として挙げている。

段階2までの実装の `src/wasm.zig` は、この両方からはみ出している。次のものを `std.heap.wasm_allocator` から直接確保し、計上しない。

- 出力バッファ。初期化のときに固定の大きさ(256 KiB)で1回だけ確保し、伸ばさない。
- ホストの入力領域。`sucheme_alloc` の呼び出しごとの確保で、ホストが `sucheme_free` で返す。起動と終了に限らない。
- 入力領域ごとの記録(`regions`)。入力領域1件につき1件で、`sucheme_free` で減る。
- `sucheme_eval_begin` の呼び出しごとのアリーナ。呼び出しの終わりに解放する。

2026-10-15 の整合性レビューで、設計書と実装の食い違いとして見つかった。設計書に合わせて計上するか、例外として認めるかを決める必要がある。

## 決定

例外として認める。実装は変えず、設計書の側を実装に合わせる。

- 計上の対象は、Scheme の値と、そのペイロードとして Scheme の実行が作るものとする。ホストとの境界に置くバッファ(出力バッファ、入力領域、その記録、1回の評価の入口で使うアリーナ)は、エントリ層の例外として、計上の外に置く。
- 例外の範囲は、`src/wasm.zig` が直接確保するものに限る。Scheme の値やそのペイロードは、エントリ層では確保しない。
- `src/wasm.zig` のコメントと、architecture.md、runtime.md、platform-and-web.md に、この例外を書く。

選ばなかった案は次のとおりである。

- 設計書に合わせて、これらを計上の対象にする案。上限が出力バッファや入力まで含めた全体の上限になる。しかし入力領域は、ホストが `sucheme_init` の前から確保でき、上限を持つヒープが無い時点でも存在する。計上するには、ヒープとは別の計上の置き場が要る。1回の評価の入口で、上限に達したときの失敗の経路も増える。得られるのは、ホストが自分の意思で渡す入力の量を、上限に含められることだけである。

## 結果

- メリット: 実装を変えずに、設計書と実装の食い違いが無くなる。エントリ層の確保が `wasm.zig` の中に限られ、範囲が読み取れる。
- デメリット・受け入れたトレードオフ: `heap_limit_bytes` は、WASM のメモリ全体の上限ではない。ホストが `sucheme_free` を呼ばずに `sucheme_alloc` を重ねると、計上されないまま増える。出力バッファの大きさは固定なので、WASM のメモリの下限はその分だけ大きくなる。
- 将来の見直し条件: ホストが渡す入力の量を、上限で抑える必要が出たとき(たとえば、Web UI が大きなファイルを扱うようになったとき)。ポートが入る段階5で、ポートのバッファは、runtime.md の表に従って計上の対象にする。そのとき、入力領域の扱いも見直す。
