# ADR-0039: 最上位の初期環境は初期化で `(scheme base)` を読み込んで作り、読み込みもヒープの上限に計上する

- ステータス: 採用
- 日付: 2026-10-19

## 背景

[ADR-0037](0037-core-library-exposed-in-stage-2.md) は、`(sucheme core)` の公開を段階2の間に限り、段階3の `(scheme base)` を構成するスライスで取り消すと決めた。スライス 3k で `lib/scheme/base.sld` などが入ったので、スライス 3l が取り消しを行う。取り消すと、次の3つを決める必要が生じた。

- REPL と CLI と WASM の最上位が何を見るか。段階2までは `(sucheme core)` の全部だった。
- 利用者が `(import (sucheme core))` を書いたときの扱い。`cond-expand` の `(library (sucheme core))` も同じ判定を通る。
- 標準ライブラリの読み込みが、ヒープの上限(`heap_limit_bytes`)の計上に入るかどうか。入ると、小さな上限では読み込めない。

## 決定

最上位の初期環境は、`Interpreter.init` 系の入口が、空の最上位に `(import (scheme base))` を評価して作る。REPL の最上位は、R7RS 5.7 のとおり、`(scheme base)` が輸出するものだけを見る。`%` で始まる内部の名前は見えない。

- 読み込みは、ストレスモード(1ステップごとの GC)を外して行い、あとで戻す。ケースごとにインタプリタを作るテストが、ストレスのかかった読み込みで何倍も遅くなるのを避けるためである。読み込んだあとのプログラムの実行は、ストレスモードのままである。
- 読み込みに使うヒープは、ほかの確保と同じく上限に計上する。入りきらない上限では、`init` は `OutOfMemory` を返し、WASM は状態コード -7(この上限では初期化できない)を返す。同じ上限での再試行も同じ結果になるので、-7 の定義([platform-and-web.md](../design/platform-and-web.md))と矛盾しない。
- `(sucheme core)` の `import` は、呼び出しの元が、実行ファイルに埋め込んだ `lib/` のライブラリのときだけ通す。判定は、読んでいるソースの積み(`ctx.sources`)の最も内側が埋め込みの根であるかで行う(`Context.coreImportable`)。拒否は `bad import: the library (sucheme core) is only for the standard libraries the executable carries` である。`cond-expand` の `(library (sucheme core))` は、同じ判定の結果を返す。
- 機械と展開器の単体テストと、`(sucheme core)` の名前を直接呼ぶ低水準の Scheme のテストは、標準環境の読み込み費用と上限への制約を受けないよう、コアを直接見る入口(`Interpreter.initCore` 系、`Context.core_open`)を使う。製品の経路はこれらを使わない。Scheme のテストのランナーは、ファイルに `# env: core` の行があるときだけ、その入口を使う。
- 準拠マトリクスは、標準ライブラリごとに、何も束縛していない最上位(`Interpreter.initBare`)でそのライブラリだけを `import` し、`isBound` で数える。ほかのライブラリや初期環境が束縛している名前は数えない。

選ばなかった案は次のとおりである。

- 標準ライブラリの読み込みを上限に計上せず、利用者のプログラムのぶんにだけ上限を課す案(上限に読み込みのぶんを足す)。ホストが指定した上限の意味が「利用者のプログラムが使える量」になり、読み込みの量が変わるたびに合計が変わる。[platform-and-web.md](../design/platform-and-web.md) は上限を「すべての合計に対する上限」と定めており、それと食い違う。計上に入れても、小さな上限が -7 になるだけで、利用者に損失は無い。
- 最初の評価の直前まで、標準ライブラリの読み込みを遅らせる案。初期化が軽くなる。しかし最初の評価が、ホストの指定した上限の外で失敗しうる場所になり、`sucheme_reset` のあとの状態も複雑になる。
- `(sucheme core)` をテストごとに `import` できるままにして、REPL の初期環境だけを替える案。ADR-0037 の取り消しの条件を満たさない。

## 結果

- メリット: 利用者が見る名前は、R7RS が定める標準ライブラリの輸出だけになる。内部の名前の漏れがなくなる。準拠マトリクスが、実際に `import` できるものを数える。
- デメリット・受け入れたトレードオフ: インタプリタを作るたびに `(scheme base)` を読み込む費用がかかる(測り方と結果は [plans/0016-phase3-scheme-stdlib.md](../plans/0016-phase3-scheme-stdlib.md) の進捗に書く)。ホストが `heap_limit_bytes` に標準ライブラリが入らない小さな値を渡すと、初期化が -7 になる。段階2に書かれた `(import (sucheme core))` を含む利用者のコードは動かなくなる。v0.3.0 のリリースノートに書く(3r)。
- 将来の見直し条件: 初期化の費用がホストの起動時間に響くとき(読み込んだライブラリの表を複数のインタプリタで共有する形を検討する。ライブラリの表を上限に計上する課題と同時に決める。roadmap のスライス 3o)。
