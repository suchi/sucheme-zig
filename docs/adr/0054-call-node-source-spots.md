# ADR-0054: 手続き呼び出しの節点に、詰めた位置(スポット)を持たせ、誤りを起こした最も内側の呼び出しの位置を診断に載せる

- ステータス: 採用
- 日付: 2026-11-22

スライス 8g-1([plans/0030-phase8-web-ui.md](../plans/0030-phase8-web-ui.md) の決定5)の設計である。計画書の合意で、方針(手続き呼び出しの節点だけに位置を複写し、誤りを起こした最も内側の呼び出しの位置を診断に載せる。マクロの展開で失われる位置は、位置なしで動く)は決まっている。この ADR は、実装で選んだ細部を記録する。

## 背景

位置の副表(`src/positions.zig` の `Table`)は、1つのトップレベルの形式を展開し終えるまでの作業表で、実行時の誤りには位置が出ない([design/frontend.md](../design/frontend.md) の位置情報)。副表を永続にすると、鍵のペアの番地が回収のあとで使い回され、無関係な位置を指す。そこで、実行時にも要る位置は、節点に複写する([design/runtime.md](../design/runtime.md) のコアIR)。節点は GC ヒープのオブジェクトで、`Node` は共用体なので、1つの変種を大きくすると、すべての節点が同じだけ大きくなる。副表のファイル番号は、入力ごとの表に対する番号で、節点より先に消える。

## 決定

1. 位置は `Spot`(8 バイトに詰めた、ファイル、行、桁)として `Node.call` の `Call.at` に持つ。ファイルは 16 ビット、行と桁は 24 ビットである。行が 0 の値は「位置なし」である。どれかが幅を超えるときは、位置なしにする(誤った位置を出さない)。
2. `Spot` のファイルは、`Context.source_names`(`positions.Names`)の番号である。名前は、同じ名前を1つにまとめて、インタプリタの間ずっと持つ。確保は `Context.resident()`(上限に数える)で行う。副表のファイル番号は入力ごとの番号なので、展開器が節点を作るときに、名前でこの表の番号に直す。
3. 複写するのは、リーダが位置を記録したペアそのものを展開した呼び出しだけである。マクロの出力のペアと、展開器が作る呼び出し(本体の定義をまとめた即時の呼び出しなど)は、位置を持たない。実行ファイルに埋め込んだ標準ライブラリの中の呼び出しも、位置を持たない(利用者が書いていない位置を出さない)。展開の誤りの位置は、これまでどおり、位置を持たない形式が、それを含む形式の位置を引き継ぐ(`Task.site`)。この引き継ぎを節点には使わない。
4. 機械は、`call` 節点の適用(`apply`)が `Raised` を返したときに、その節点の位置を `Context.raised_call` に、送出された値と組にして置く。位置を持たない節点は、置かず、前の値も消さない。呼び出しでない節点の誤り(未束縛の変数の参照など)は、置かないので、位置が出ない。値が違えば使わない(`raisedPosition` と同じ)ので、前の誤りの位置は、別の値の誤りには出ない。値は GC のルートである。
5. ファイルを持たない入力(REPL の行、標準入力、WASM の入力)も、空の名前のファイルとして、位置を記録する。診断は、REPL、WASM、ファイルのすべてで、位置が分かる誤りを `line:column: message` の形(ファイル名があれば `name:line:column: message`)にそろえる。理由は、8g-2 が WASM の出力から行と桁を取り出す前提であることと、入口ごとに形を変えないことである。位置が無い誤り(呼び出しでない節点の誤り、位置を持たない呼び出しの誤り)は、これまでの形のままである。この形の変更で、`tests/scheme` と利用者向けの文書の期待出力、`tools/test-wasm` の期待が変わる。
6. 診断は、実行時の誤りに呼び出しの位置があれば、それを使い、無ければ、展開の位置か、最上位の形式の位置(これまでの挙動)を使う。

## 結果

- メリット: 実行時の誤り(型、引数の数、`raise`、`error`)が、呼び出しの位置を持つ。ネイティブと WASM が、同じ形式で位置を出す。節点の増え方が、呼び出しの数ではなく、節点の数に比例する(共用体のため)。増えた分は、節点の大きさとして、ヒープの上限に数えられる。
- デメリット・受け入れたトレードオフ:
  - 共用体の幅が増えるので、呼び出しでない節点も大きくなる(測定は PR にある)。
  - 行が 2^24 を超える入力や、ファイルが 2^16 を超える名前は、位置なしになる。
  - 標準ライブラリの手続き(Scheme で書いたもの)の中で起きた誤り(`list-ref` の範囲外など)は、位置を持たない。利用者の呼び出しの位置も出ない(その呼び出しは、手続きに入った時点で継続から外れており、辿る手段が無い)。
  - 位置を持たない呼び出し(マクロの出力)で起きた誤りは、前の呼び出しの位置を引き継がない。出ないだけである。
  - REPL、標準入力、WASM の診断の形が変わる(位置が分かる誤りに `line:column: ` が前置される)。期待出力の書き換えが広い(PR 本文に一覧)。
- 将来の見直し条件: 呼び出しでない節点の位置が要るとき(全節点に複写する案)。継続を辿った呼び出しの並び(スタックトレース)が要るとき。マクロの出力に、使用の位置を引き継ぐとき。
