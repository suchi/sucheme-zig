# ADR-0025: 承認の判断はフックに置き、許可リストは日常操作まで広げる

- ステータス: 採用
- 日付: 2026-10-08

## 背景

Claude Code の承認は、ツール名とコマンドの接頭辞で照合される。`.claude/settings.json` の `permissions.allow` に一致した呼び出しは確認なしに実行され、それ以外は1回ごとに確認を求める。

段階0の作業では、確認の回数が判断の質を下げる形で効いた。許可は検証コマンドだけで、`git add`・`git commit`・ファイルの編集・実機確認のハーネスは毎回確認を求めていた。さらに、引数が毎回違う一度きりのコマンドはどの接頭辞にも一致しないため、同じ種類の操作を繰り返すと回数分の確認が出た。敵対的レビューのサブエージェントも同じ設定で動くので、1巡でまとまった回数になった。

確認が多いこと自体が安全を増やすわけではない。同じ文面の確認が連続すると、読まずに通す方向に圧力がかかる。守るべき操作の確認が、その他の確認に埋もれる。

一方で `permissions` だけでは守れない集合が2つある。シークレットファイルの `deny` は Read ツールにしか効かず、`cat` や `grep` には効かない。ガードレール設定を守るフックは Edit と Write にしか登録しておらず、リダイレクトや `sed -i` には効かなかった。許可リストを広げると、この2つの穴が広がる。

## 決定

承認の判断をフックに寄せ、許可リストは日常操作まで広げる。

### 許可リストが持つもの

`allow` には読み取りと、フィーチャーブランチ上の日常の開発操作を置く。ビルドとテスト、`git` の読み取りと `add`・`commit`・`push`、`gh` の読み取り、シェルの基本コマンド、ファイルの編集(`defaultMode` を `acceptEdits` とする)である。

`ask` には、外部に出るものと履歴を書き換えるものと削除を置く。PR の作成・編集・コメント・レビュー・クローズ・マージ、Issue、リリース、`merge`・`rebase`・`reset`・`revert`・`checkout`・`restore`・`tag`、`rm` である。`allow` に無いものを既定で確認する形に任せず列挙するのは、確認を求める理由が種類ごとに違うからである。列挙が残っていれば、後から許可に移すときにその理由を読み直せる。

一覧は `.claude/settings.json` が正であり、ここに複製しない。

### フックが守るもの

フックの判定は許可リストより優先される。許可に一致していても、フックが `ask` を返せば確認が出て、`deny` を返せば実行されない。守るべき集合はここに置く。

`.claude/hooks/protect-config.sh` を Edit・Write と Bash の両方に登録し、2つの集合を持たせる。シークレットファイルは `deny` する。ガードレール設定(`.claude/settings.json`・`.claude/hooks/`・`.github/workflows/`・`.github/dependabot.yml`)は `ask` する。

Bash はコマンドの文字列で照合する。シェルはリダイレクト・`sed -i`・`cp`・`mv` で前者に書き込み、`cat`・`grep` で後者を読むので、ツールの種類では区別できない。照合は粗く、文字列のどこに現れても一致させる。書き込むコマンドと名前を挙げるだけのコマンドを区別せず、相対パスが錨をすり抜けることもない。多めに確認が出る側に倒す。これらのファイルは Bash ではなく Read ツールで読む。Read には `deny` が効く。

同じフックが `--build-file` も確認にする。許可リストは接頭辞で照合するので、`zig build` の許可は `zig build --build-file <任意のパス>/build.zig` を含み、それは configure 段でそのファイルの Zig コードをホストで実行する。コマンドのどこに現れるか決まっていないフラグを接頭辞では除けないため、フラグ側をここで持つ。

`.claude/hooks/block-dangerous-git.sh` が持つ禁止と確認は変えない。`main` への直接プッシュ・`main` への force push・`--no-verify` は禁止のまま、force push・`reset --hard`・`clean -f`・`branch -D`・`main` 上のコミット・`curl ... | sh` は確認のままである。

### この決定が約束しないこと

許可リストを広げた範囲は、フックが見ていない破壊を含む。`sed -i` と `cp` と `mv` は、ガードレール設定とシークレット以外のどのファイルでも上書きできる。これは Edit と Write が元から持っていた権限と同じで、増えたのは確認が出ないことだけである。作業ツリーの取り違えに対する防壁は git の履歴である。

任意のコードを実行するものを `allow` に入れない。フックはコマンドの文字列を見るので、スクリプトの中身には効かない。`python` は全面では許可せず、実機確認のハーネスの置き場所をパスの接頭辞にした形だけを許可する。

フックの判定そのものに自動検査は無い。守る側と通す側の両方のペイロードを手で流して確かめている。検査として足す検討は [docs/design/open-questions.md](../design/open-questions.md) にある。

## 結果

同じ種類の操作が確認なしで繰り返せるようになり、確認が出たときはそれが守るべき操作であることを意味する。

許可リストを緩めても、シークレットとガードレール設定は貫通しない。

`permissions` の変更も `.claude/hooks/` の変更も、引き続きユーザーの承認が要る(AGENTS.md のセキュリティの節)。この ADR はその承認の対象を狭めない。
