# ADR-0009: WASM は freestanding とし、Web UI は依存パッケージを持たない

- ステータス: 採用
- 日付: 2026-10-04

> 2026-10-06 追記: 本ADRの決定(`wasm32-freestanding`、依存パッケージを持たない `web/`)は変わらない。以下の本文が配置先として挙げている GitHub Pages は使わないことになった([ADR-0021](0021-no-github-pages-defer-hosting.md))。依存ゼロの方針はこの変更と相性がよく、成果物が静的ファイルだけなので置けるサービスを自由に選べる。`SharedArrayBuffer` を採らない理由も変わらない。COOP と COEP のヘッダを設定できる保証が、配置先を決めない段階ではないためである。

## 背景

要件として「いずれの段階でも簡単な Web の UI から実行できるサブプロジェクトの仕組み」と「GitHub Pages で Web UI が試せる」ことが与えられている。

WASM のターゲットには `wasm32-wasi` と `wasm32-freestanding` がある。WASI をブラウザで動かすには shim ライブラリが必要になる。

Web UI の実装には、バンドラとフレームワークを使う構成と、素の HTML・CSS・JavaScript による構成がある。

## 決定

`wasm32-freestanding` を対象とする。ホストに要求する import 関数は標準出力への書き込み、標準エラーへの書き込み、現在時刻の3つに限る。

Web UI は npm パッケージ、バンドラ、CDN を使わない素の HTML と CSS と JavaScript モジュールで構成する。`web/` 以下に置き、ビルド成果物の `sucheme.wasm` をコピーするだけで GitHub Pages に配置できる状態を保つ。

インタプリタは Web Worker 上で動かす。機械は歩数制限で制御を戻す設計なので([ADR-0004](0004-cek-machine-evaluator.md))、長時間の計算中も画面が応答し、停止ボタンが機能し、`read` による対話も実現できる。

`SharedArrayBuffer` と `Atomics.wait` による入力待ちは採用しない。この方式は COOP と COEP のレスポンスヘッダを必要とし、GitHub Pages ではヘッダを設定できない。再開可能な機械であればヘッダなしに同じ目的を達成できる。

## 結果

- メリット: GitHub Pages への配置がファイルのコピーだけで済む。供給連鎖上の面を増やさず、Dependabot の対象エコシステムも増やさない。WASI shim の仕様変更に追随する必要がない。成果物が小さい。
- デメリット・受け入れたトレードオフ: ファイル入出力はブラウザでは埋め込み仮想ファイルシステムの読み取りに限られる。Web UI の見た目と機能を自前で作る必要があり、高機能なエディタ部品は使えない。
- 将来の見直し条件: Web UI に高度な編集機能(構文強調、補完)が必要になり自前実装の負担が大きいと判断した場合、単一ファイルで配布できるライブラリをリポジトリに取り込む方式を検討する。npm 依存の導入は改めてADRを書く。
