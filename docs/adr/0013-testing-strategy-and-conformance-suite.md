# ADR-0013: テストは3層構成とし、外部の準拠スイートをベンダリングする

- ステータス: 採用
- 日付: 2026-10-04

> 2026-10-23 追記: ファジングの対象に、リーダに加えてインタプリタ全体を通す対象を足した。決定は [ADR-0045](0045-fuzz-the-whole-interpreter.md) にある。リーダのファジングの決定は変えていない。

## 背景

R7RS 準拠を主張するには、仕様の広い範囲を網羅する検証が必要である。自作テストだけでは見落としが避けられず、外部の準拠テストスイートを使うのが一般的である。

chibi-scheme に含まれる `r7rs-tests.scm` は、R7RS-small 小委員会の議長である Alex Shinn が維持しており、複数の処理系が準拠検証に使っている事実上の標準スイートである。ライセンスは BSD 3条項である。

外部コードの取り込みには、ビルド時に取得する方式とリポジトリに取り込む方式がある。

## 決定

テストを3層で構成する。

| 層 | 対象 | 置き場所 | 実行 |
| --- | --- | --- | --- |
| 単体テスト | Zig の各モジュール。リーダ、プリンタ、GC、照合器、数値演算 | 各 `.zig` の `test` ブロック | `zig build test` |
| 振る舞いテスト | Scheme レベルの意味論。末尾再帰、継続、衛生性、例外、循環構造 | `tests/scheme/` | `zig build test-scheme` |
| 準拠テスト | 外部スイートによる網羅的検証 | `tests/vendor/` | `zig build test-conformance` |

`r7rs-tests.scm` をリポジトリに取り込む。ビルド時にネットワークから取得しない。再現可能なビルドを保ち、供給連鎖上の面を増やさないためである。

取り込みにあたって次を守る。

- `tests/vendor/README.md` に、取得元のリポジトリ、取得時のコミットハッシュ、取得日、ライセンス名を記録する。
- ライセンス全文を `tests/vendor/` 以下に同梱する。
- 取り込んだファイルを改変しない。処理系側の制約で実行できない部分は、除外リストを別ファイルに置いて管理する。
- 更新は手動の作業とし、差分をレビューする。

スイートは `(chibi test)` という移植可能な R7RS で書かれたモジュールを使うため、互換の最小実装を自作して `lib/` 側に置く。

リーダに対してはファジングを行う。Zig 0.17.0 の `std.testing.fuzz` を使う。

準拠テストの結果は準拠マトリクスの生成に使う([r7rs-coverage.md](../design/r7rs-coverage.md))。

## 結果

- メリット: 自作テストの見落としを外部スイートが補う。合格数という客観的な進捗指標が得られる。オフラインでビルドとテストができる。
- デメリット・受け入れたトレードオフ: 外部コードをリポジトリに持つため、ライセンス表示の維持が必要になる。上流の更新に自動で追随しない。スイートが前提とする振る舞いが仕様の解釈を含む場合、合格しないことが必ずしも不準拠を意味しないため、除外リストの判断に根拠を残す必要がある。
- 将来の見直し条件: 他の準拠スイートが利用可能になった場合、層を増やして併用する。除外リストが増えた場合は、各項目の理由を見直して仕様の解釈をADRに記録する。
