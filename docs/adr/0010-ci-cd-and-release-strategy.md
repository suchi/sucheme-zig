# ADR-0010: CIのテストは Linux と Windows に限り、macOS はビルド保証のみとする

- ステータス: 採用
- 日付: 2026-10-04

## 背景

要件として GitHub Actions による CI/CD と、節目ごとの GitHub Release が与えられている。

GitHub Actions の課金は OS ごとに単位が異なり、macOS ランナーは Linux の10倍の実行分数として計上される。ユーザーから、macOS 対応はコードとしては必要だが、テストによる動作保証は Windows と Linux だけでよいという指示を受けた。

Zig は1つのランナーから全対象へクロスコンパイルできる。Windows から x86_64-linux-musl、aarch64-linux-musl、x86_64-macos、aarch64-macos、aarch64-windows の5つへのビルドが成功することは実機で確認した。

## 決定

| ワークフロー | 契機 | 内容 |
| --- | --- | --- |
| CI | push と PR | `AGENTS.md` の検証コマンド表のうち、CIで実行する列が「全コミット」で、かつその時点の段階で使えるものすべて。段階が進むにつれて対象が増える |
| ~~Pages~~ | - | 廃止。[ADR-0021](0021-no-github-pages-defer-hosting.md) により配置を行わない。WASM と Web UI のビルドは CI に含め、成果物を zip で添付する |
| Release | `v*` タグ | 全ターゲットのクロスコンパイル、チェックサム、リリースノート、成果物の添付 |

CI のテスト実行は `ubuntu-latest` と `windows-latest` の2つに限る。macOS はリリース時のクロスコンパイルによるビルド保証のみとし、自動テストによる動作保証の対象外とする。この範囲は README とリリースノートに明記する。

リリース成果物のクロスコンパイルは `ubuntu-latest` の1ジョブで行う。対象は次の6つとする。この一覧が正であり、他の文書は件数を書かずにここを参照する。

| ターゲット | 備考 |
| --- | --- |
| `x86_64-linux-musl` | 静的リンク |
| `aarch64-linux-musl` | 静的リンク |
| `x86_64-macos` | テストによる動作保証なし |
| `aarch64-macos` | テストによる動作保証なし |
| `x86_64-windows` | |
| `aarch64-windows` | |

macOS バイナリの署名と公証は行わない。

節目のリリースは段階の完了に対応させる。段階1の完了を v0.1.0 とし、以降の段階ごとにマイナーバージョンを上げる。R7RS 準拠の達成を v1.0.0 とする。

ファジングは全コミットの CI に入れない。`--fuzz` が自律的に停止しないためである。別のワークフローを定期実行(スケジュール起動)と手動起動で動かす。

CI のテスト実行対象は `ubuntu-latest` と `windows-latest` で、いずれも x86_64 である。aarch64 のバイナリはクロスコンパイルで生成するが、自動テストは実行しない。ランナーの構成が変わって aarch64 が利用できるようになった場合は、このADRを更新してから対象に加える。

WASM はビルドと、Node.js 上でのエクスポート呼び出しの往復テストを `ubuntu-latest` で実行する。これが CI で WASM を検証する範囲の全体である。ブラウザ自動化は行わない。

(2026-10-06 追記: ブラウザでの動作確認を Pages のプレビューで行うとしていたが、[ADR-0021](0021-no-github-pages-defer-hosting.md) で配置をやめた。CI の成果物として `sucheme.wasm` と `web/` を zip で添付し、ローカルで開いて手動確認する。段階8で配置したあとは、その URL でも確認する。)

Zig のバージョンは CI でも固定し、`.zigversion` と一致させる。

## 結果

- メリット: 課金を抑えつつ、Windows と Linux という利用者の多い環境で動作を保証できる。クロスコンパイルを1ジョブに集約することで、リリースの所要時間と課金が小さくなる。
- デメリット・受け入れたトレードオフ: macOS 固有の不具合(パス処理、端末制御、ファイルシステムの大文字小文字の扱い)が自動検出されない。macOS 利用者からの報告に依存する。署名がないため macOS での実行には利用者側の操作が必要になる。
- 将来の見直し条件: macOS 固有の不具合が実際に報告された場合、該当部分のみを対象とした最小の macOS ジョブを、タグ時またはリリース前の手動実行に限って追加する。常時実行にはしない。
