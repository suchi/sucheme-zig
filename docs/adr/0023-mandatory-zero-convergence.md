# ADR-0023: 自前の敵対的レビューの収束条件を必須の新規指摘ゼロとする

- ステータス: 採用
- 日付: 2026-10-07
- 置き換え: [ADR-0017: self-hosted-adversarial-review](0017-self-hosted-adversarial-review.md) を非推奨とし、本ADRが最新の決定となる

## 背景

ADR-0017 は自前の敵対的レビューを一次のレビューとし、収束条件を新規指摘ゼロと定め、「新規指摘ゼロのルールは緩めない。収束は検出器の調整で行い、基準を下げて収束させない」と書いた。

段階0でこの条件が成立しなかった。巡ごとの指摘数が下降せず、各巡の指摘の大半が直前の巡で書いた修正文そのものの欠陥である。件数の推移は [docs/review/stage0-findings.md](../review/stage0-findings.md) の表が正で、ここに複製しない。本ADRが定める規律の1つが「実測値を散文に書かない」であり、ADR は本文を書き換えられないので、陳腐化する数をここに置かない。

ADR-0018 が加えた2つの手段(主張の置き場所を変える、決定の時期を遅らせる)は実際に効いた。再発した類型のうち検査にできるものは `tools/check-docs` に移し、移した検査がその場で同種の誤りを捕まえた実例もある。それでも新規指摘ゼロには届かない。全面再走査が、増え続ける文書の中から既存の記述を拾い直すためである。

## 決定

収束条件を「必須の新規指摘ゼロ」とする。

必須とは次の2つである。

- 検証コマンドが緑のまま穴が開くもの。
- 記録された事実が誤っているもの。

推奨と任意の新規指摘は `docs/review/` に記録し、該当する段階の作業項目に回してよい。記録せずに閉じることは引き続き認めない([ADR-0018](0018-incremental-vertical-slices.md))。

この判断はユーザーが行った。足場の品質は必須で担保され、推奨と任意の大半は文書間の細部の不一致であって、実装が進むと実コードとの突き合わせで検出される、という判断である。

### 基準を下げたのではなく、対象を分けた

必須の扱いは変えていない。必須が1件でもあれば収束していない。変えたのは、推奨と任意を同じ巡で閉じることを求めない点である。

あわせて、巡をまたいで再発した類型は散文の注意書きではなく `tools/check-docs` の検査として足すことを規律とする。「こうなっている」と文書や doc コメントに書いて機械が検査しない形が、次の巡の指摘を確実に生む。実測値を散文に書かない。件数や不合格の数を書く代わりに、検証コマンドを実行して確かめる形にする。

### 外部レビューの扱いは変えない

ADR-0017 の「外部レビューの可否をマージの条件に含めない」はそのまま引き継ぐ。`AGENTS.md` の PR 手順が持つ、自前のレビューが収束したあとで Copilot に1回依頼する任意の段も変えない。

### 手順の正は AGENTS.md

PR の手順と収束条件の運用は `AGENTS.md` の「PR・レビュー・マージ」の節が正である。本ADRは判断とその理由を記録する。手順を本ADRに複製しない。

## 結果

- メリット: 足場の品質を落とさずに段階1へ進める。推奨と任意を記録して回すので、指摘が失われない。再発類型を検査に移す動機が規律として残る。
- デメリット・受け入れたトレードオフ: 推奨と任意の積み残しが段階をまたいで増える。`docs/review/` の記録が読まれなければ、回したものが戻ってこない。必須の判定がレビュア側の裁量に依存する。
- 将来の見直し条件: 積み残しが段階の完了判定を妨げるようになった場合、または必須の判定が巡ごとに揺れるようになった場合、本ADRを非推奨にして新ADRを書く。
