# ADR-0042: 値の無いまま置き換えた最上位のセルは、未束縛の報告のために表が持つ

- ステータス: 採用
- 日付: 2026-10-21
- 一部置き換え: [ADR-0040: core-ir-in-the-gc-heap](0040-core-ir-in-the-gc-heap.md) の決定5のうち、`displaced_cells` をやめる部分を置き換える。値を持つセルを表が持ち続けないこと、定義に失敗したライブラリの表を手放すことは変わらない

スライス 3o-4([plans/0023-slice-3o-ir-to-gc-heap.md](../plans/0023-slice-3o-ir-to-gc-heap.md))の実装の中で見つかった食い違いに対する判断で、2026-10-21 にユーザーが承認した。

## 背景

ADR-0040 の決定5は、表から外れたセルを持ち続ける保持(`env.Global.displaced_cells`)を、コードが GC ヒープに入ったので要らなくなるとして、やめるとした。計画書 0023 の 3o-4 も、`displaced_cells` を消すとした。

3o-4 の実装で、`displaced_cells` にもう1つの使い道があることが分かった。ライブラリの本体の終わりの未束縛の検査(`src/syntax/library.zig` の `unboundNames`)が、このリストを読む。本体が名前を参照すると、その最上位自身の未束縛のセルができる。そのあと `import` か `define-syntax` がその名前を置き換えると、セルは表から外れ、このリストにだけ残る。本体の終わりにセルが値を持たなければ、その名前を未束縛として報告する。`tests/scheme/0162-define-library.txt` が、インポートの前に参照した名前の報告として、この挙動を固定している。ADR-0040 と計画書 0023 は、この使い道に触れていなかった。

## 決定

`displaced_cells` を `displaced_unbound` に変え、`import` か `define-syntax` が置き換えたときに、まだ値の無い自分のセルだけを持つ。値を持つセルは持たない。前に展開したコードがまだ指していれば、ADR-0040 のとおり、そのコードから辿られる。

検討した選択肢:

- 置き換えた時点でエラーにする案。保持は要らなくなるが、エラーの時点と内容が変わり、本体の終わりにまとめて報告していた他の未束縛の名前が出なくなる。
- 計画どおりリストを消し、置き換えた名前を報告しない案。本体の終わりまで値の無い参照が、エラーにならずに通り、R7RS の誤りを見逃す。

## 結果

- メリット: 未束縛の報告の挙動は変わらない。値を持つセルは、表から外れれば、指すコードが無いときに回収される。
- デメリット・受け入れたトレードオフ: REPL の表では、未束縛の名前を参照してから、その名前をインポートするか `define-syntax` で定義したときに、値の無いセルが1つずつ残る。REPL はこのリストを読まないので、報告には使われない。同じ名前のセルが2回以上残るのは、失敗した展開が置き換えを戻したあとに、もう一度置き換えたときに限る。
- 将来の見直し条件: REPL の表に残る値の無いセルが、上限に対して無視できない量になるとき。未束縛のセルを弱く持つ設計(ADR-0040 の決定6、スライス 3o-5)と合わせて、REPL の表では持たない形を検討する。
