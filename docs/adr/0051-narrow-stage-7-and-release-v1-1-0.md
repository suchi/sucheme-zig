# ADR-0051: 段階7の範囲を改め、識別子の補完と差分読み取りを外して v1.1.0 を出す

- ステータス: 採用
- 日付: 2026-11-21

## 背景

[roadmap](../roadmap.md) の段階7は、完了条件を「要件どおりの編集操作ができる。リリース v1.1.0 を出す」と書き、作業項目に識別子の補完(スライス 7k)と、REPL の継続行の差分読み取り(スライス 7l)を含んでいた。2つとも着手していない。

- 7k は、現在の環境の束縛名を列挙する API(L0 の `src/sucheme.zig`)を待つ。
- 7l は、L2 が所有する `src/reader.zig` の変更に及ぶ。

一方、行編集の核と、核のあとの括弧の対応表示(7e)、複数行の編集(7m)、履歴の保存(7n)、Windows の生モード(7i)は、main に入っている。先行版 `v1.1.0-pre.2` が、これらを含む形で配られた。Windows のコンソールでは、複数行の編集、履歴、Emacs 風のキー割り当てが、2026-11-21 に実機で確かめられた。

この状況で、段階の完了条件と、リリースを出す作業の関係を整理した。

- 段階の完了条件は、編集操作が要件どおりできることである。リリースを出す作業は、完了条件を満たしたかどうかの判定に含めない。リリースは、完了した状態を配る手続きである。
- 7k と 7l を待つと、すでに使える編集機能が、v1.0.0 のあとの通常のリリースに載らないまま続く。

## 決定

1. 段階7の範囲から、7k(識別子の補完)と 7l(差分読み取り)を外す。段階7の完了条件は、「要件どおりの編集操作ができる」を、補完と差分読み取りを除いた範囲で読む。
2. 外したものは、roadmap の「段階7の後続の作業」の節に残す。どの段階のリリースにも属さない作業として置き、各項目に、待つものと、着手の前提を書く。ここには、7k と 7l のほか、すでに計画書 0021 にあってどの段階にも割り当てられていなかった、7o(端末の高さを超える描画)、7p(貼り付けの描画の畳み込み)、文字幅の表の差し替え(7f)、評価だけを止める Ctrl-C も置く。
3. 現在の品質を、通常のリリース v1.1.0 として出す。リリースノートの既知の制限に、次を書く。
   - 識別子の補完が無い。
   - 差分読み取りが無い。閉じ忘れを含む 64 KiB 近い貼り付けでは、費用が保留の大きさの2乗に比例する(再現の仕方は roadmap の後続の作業の項目にある)。
   - Windows の実機での確認は一部だけである。複数行の編集、履歴、Emacs のキーは確かめた。終了時のモードの復元、日本語の入力と表示、旧来のコンソールは確かめていない。
   - 全角の文字の幅が仮の実装で、カーソルの位置がずれる。
   - 評価の間の Ctrl-C は、sucheme を終える。
   - v1.0.0 の既知の制限のうち、残っているもの。
4. `docs/manual/guide/03-repl.md` を、実装に合わせて直す。Windows の行編集、括弧の対応の表示、履歴の保存の記述が、実装に追いついていなかった。

## 検討した別案

- 7k と 7l を終えてから v1.1.0 を出す(元の計画)。補完は L0 の API を待ち、差分読み取りは L2 の変更に及ぶので、いつ終わるかが、行編集の外の作業の進み具合で決まる。実際には使える機能の配布が、その間止まる。採らなかった。
- 7l だけを段階7に残す。費用が2乗になる再現が、REPL の既知の制限として v1.0.0 から続いており、保留の上限(64 KiB)を下げずに、この制約を受け入れている。直さなくても、結果は正しい。採らなかった。

## 結果

- メリット: 使える編集機能が、通常のリリースとして届く。段階の完了条件と、リリースの手続きの区別が、文書に残る。外した作業が、割り当てのない状態にならず、roadmap に行き先を持つ。
- デメリット・受け入れたトレードオフ:
  - v1.1.0 に補完が無い。端末で Tab を押すと、文字が入る。
  - 閉じ忘れを含む大きな貼り付けで、費用が保留の大きさの2乗になる。結果は正しいが、待たされる。
  - Windows の実機で確かめていない範囲があり、崩れる可能性がある。崩れたときは、パイプで入力すると、行編集のない読み方に切り替わる。
  - roadmap の段階7の項目が、元の計画より減る。7k と 7l を入れる版は、後続の作業の着手時に決める。
- 将来の見直し条件: L0 が束縛名を列挙する API を提供したとき(7k)。L2 のリーダが、読み取りの状態を保って続きから読める形になったとき(7l)。そのときは、後続の作業の項目を、段階に割り当てる PR で扱う。
