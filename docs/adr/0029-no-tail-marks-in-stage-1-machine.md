# ADR-0029: 段階1の機械は戻り先のフレームを積まず、末尾位置の印を持たない

- ステータス: 採用
- 日付: 2026-10-09

> 2026-10-13 追記: 段階2のスライス 2c で、`apply` を最初の機械操作プリミティブとして入れた。印は足していない。`Machine.apply` は `apply` の引数を並べ直した呼び出しを、継続のフレームを積まずにその場で適用するので、`apply` の第1引数は `apply` の呼び出しの継続のもとで走り、印なしで末尾呼び出しになる。`apply` を通した末尾呼び出しのループで継続の深さ(`Machine.peak_depth`)が回数によらないことを、`src/machine.zig` のテストで確かめた。`call/cc` と `call-with-values` も、同じ形で被呼び出し側を呼び出し側の継続のもとで走らせる計画である([0014](../plans/0014-phase2-core-language.md) の「モジュール間のインタフェース」の機械の節)。決定(段階1の機械が印を持たないこと)と見直し条件は変えない。

## 背景

[ADR-0004](0004-cek-machine-evaluator.md) は、末尾位置の判定を展開器が行い、コアIRの呼び出し節点に印を付け、機械がその印を信用すると定めている。判定の責任を1箇所にまとめるためである。

切片 1f で機械を作ると、印を読む箇所がないことが分かった。機械の呼び出しは、手続きの本体を呼び出し側の継続のまま走らせる。呼び出し側が引数を評価するために積んだフレームは、引数がそろって適用に入る時点で外れている。`if` は判定のフレームを、式の列は最後の式の前に自分のフレームを外す。この形では、末尾位置の呼び出しは何も積まず、末尾でない呼び出しは評価の途中で積んだフレームの分だけ深くなる。区別は継続の形から自然に出る。

## 決定

段階1の展開器はコアIRの呼び出し節点に末尾位置の印を付けず、機械も印を読まない。末尾呼び出しが定数の継続で動くことは、機械が数える継続の深さ(`Machine.peak_depth`)をテストで比べて確かめる。

印は、末尾位置であることを機械が知らないと正しく動かない機構が入る段階で足す。ADR-0004 が末尾呼び出しを必須とする4箇所(`apply` の第1引数、`call/cc` の第1引数、`call-with-values` の第2引数、`eval`)は段階2以降の機械操作プリミティブで、継続フレームを積まずに自身の継続を引き継ぐ。印が必要になるのは、そこで被呼び出し側が末尾位置かどうかを区別しなければならない場合である。必要になったとき、展開器が付ける形で足す。

選ばなかった案は、1f で印を付けて機械が読まない形にすることである。読む箇所のない印は、正しさを何も固定せず、展開器が間違った印を付けても検査が落ちない。YAGNI に反する。

## 結果

- メリット: 展開器の判定と機械の動作が二重にならない。印が間違っているという類型の欠陥が存在しない。
- デメリット・受け入れたトレードオフ: ADR-0004 の文言(展開器が印を付ける)と、段階1の実装が一致しない。ADR-0004 に決定を変えない追記を置いた。段階2で印が要るようになったら、展開器の判定の責任をその時に1箇所へ置く。
- 将来の見直し条件: 段階2で、末尾位置であることを機械が知る必要のある機構が入るとき。
