# ADR-0015: MIT ライセンスを採用する

- ステータス: 採用
- 日付: 2026-10-04

> 2026-10-06 追記: その後リポジトリは private に戻った([ADR-0020](0020-repository-visibility-private.md))。本ADRの決定は変えない。private でもライセンスファイルを置く意味は失われず、将来公開する場合に判断をやり直さずに済む。

## 背景

リポジトリを public にする決定([ADR-0012](0012-repository-visibility-public.md))に伴い、ライセンスの明示が必要になった。ライセンスを置かない public リポジトリは全権利保留と解釈されるため、公開の意図と矛盾する。

次の制約を満たす必要があった。

- 準拠テストスイート(chibi-scheme の `r7rs-tests.scm`、BSD 3条項)をリポジトリに取り込む([ADR-0013](0013-testing-strategy-and-conformance-suite.md))ため、BSD 3条項と両立すること。
- インタプリタを他の製品へ組み込む用途を妨げないこと。

検討した選択肢は次のとおり。

- MIT: 最も短く広く使われている許諾型。条件は著作権表示と許諾表示の保持のみ。
- BSD 3条項: MIT に「名前を宣伝に使わない」条項を加えたもの。取り込む準拠スイートと同じライセンスになる。
- Apache-2.0: 特許授権の条項と変更の注記義務を含む。文言が長く、NOTICE ファイルの管理が必要。GPLv2 との非互換が知られている。

## 決定

MIT ライセンスを採用する。著作権者は suchi とする。`LICENSE` をリポジトリルートに置く。

取り込む外部コードは、そのコードのライセンスを維持したまま `tests/vendor/` 以下に置き、ライセンス全文と出典を同梱する。リポジトリ全体のライセンスが MIT であることと、`tests/vendor/` 以下が BSD 3条項であることを `tests/vendor/README.md` に明記する。BSD 3条項は MIT と同じ許諾型であり、両者を1つのリポジトリに含めることに問題はない。

`build.zig.zon` の `paths` に `LICENSE` を含め、パッケージとして配布される際にライセンスが同梱されるようにする。

## 結果

- メリット: 条件が最も少ないため、組み込み用途を含む幅広い利用を妨げない。文言が短く、利用者が読んで判断できる。ベンダリングする BSD 3条項のコードと両立する。
- デメリット・受け入れたトレードオフ: 特許に関する明示的な授権がない。変更の注記義務がないため、改変版の由来が追いにくい。いずれも本プロジェクトの規模では実害が小さいと判断した。
- 将来の見直し条件: ライセンスの変更は既存の利用者に影響するため、原則として行わない。貢献者が増え、特許に関する明示的な取り扱いが求められた場合は、Apache-2.0 への変更またはデュアルライセンス化を検討する。その場合は本ADRを非推奨にして新ADRを書き、全貢献者の同意を得る。
