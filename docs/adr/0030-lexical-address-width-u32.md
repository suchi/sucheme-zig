# ADR-0030: 字句アドレスは u32 とし、超える入れ子は実装制限として報告する

- ステータス: 採用
- 日付: 2026-10-09

## 背景

局所変数の参照は、字句アドレス(何枚外のフレームの、何番目のスロットか)で解決する([runtime.md](../design/runtime.md) の環境)。70000段の入れ子 `lambda` は16MBの上限内で作れるので、16ビットでは溢れる。溢れると、別のフレームのスロットを静かに読む。幅を決めるか、実装制限として報告するかを、切片 1f の展開器が必要にした。

## 決定

深さと添字を `u32` にする。展開器は、次の2つが `u32` に収まらないとき、`implementation restriction: ...` の条件を上げて展開を止める(R7RS 1.3.2 は実装制限の報告を許す)。

- 参照する変数が何枚外のフレームにあるか(入れ子の深さ)。
- 1つの手続きのフレームのスロット数(仮引数と本体の定義の数)。

検査は展開器の中に置き、機械は展開器が出したアドレスを信用する。上限は `Limits` に取り出し、テストは小さい値でその境界を確かめる。

選ばなかった案は次の2つである。`usize` にする案は、WASM(32ビット)とネイティブで上限が変わり、試験が環境に依存する。16ビットにして報告する案は、通常の入力で上限に当たりうる(70000段の入れ子が16MB内で作れる)。

## 結果

- メリット: 16MBのヒープでは `u32` を超える入れ子もスロット数も作れないので、実際の入力が制限に当たることはない。溢れて別のスロットを読む事故が起きない。
- デメリット・受け入れたトレードオフ: 節点が16ビットの場合より数バイト大きい。
- 将来の見直し条件: ヒープの上限を引き上げ、`u32` の入れ子が作れるようになったとき。
