# 未確定事項

設計時に決めていないことの一覧。[ADR-0018](../adr/0018-incremental-vertical-slices.md) に従い、未確定事項はこのファイルに1箇所だけ置く。各設計ドキュメントは自分の領域の未確定事項をここへのリンクで示し、内容を複製しない。

項目には「決める段階」と「何を根拠に決めるか」を書く。根拠が書けないものは、設計時に決めるべきものである可能性が高いので、その場で決める。

## 設計時に決めたので、ここには載らないもの

全体整合性に必要なものは設計時に決めてある。対象の一覧は [ADR-0018](../adr/0018-incremental-vertical-slices.md) の表が正であり、ここに複製しない。

これらを変える必要が出た場合は ADR を書く。未確定事項として扱わない。

## 段階1までに決める

| 事項 | 根拠にするもの |
| --- | --- |
| `refAllDecls(@This())` が実際に到達する位置にあることの検査 | `tools/check-docs` は字句解析なので、`comptime { if (false) ... }` のような到達しない位置に書かれた呼び出しを区別できない。意味解析か、テスト件数の期待値との突き合わせで検出する案を段階1の実装で試す |
| `refAllDecls` の修飾子が `std.testing` に解決されることの検査 | 字句解析では修飾子の意味が分からない。`const fake = struct { fn refAllDecls(_: type) void {} };` をファイル内に置いて `fake.refAllDecls(@This())` と書くと検査を通る。実機で確認した。到達性と同じ案で扱えるかを段階1の実装で見る |
| CI が表の行を走らせることの検査の範囲 | 全コミットで走るワークフローは `.github/workflows/ci.yml` と名前で決めてあり、そこに無いコマンドは満たされない。見ていないのは、ジョブが空のマトリクスで0回展開される場合と、ci.yml 自身のトリガが変わった場合である。段階1で `fuzz.yml` を足すとき、`schedule` と `workflow_dispatch` を許可キーに入れる判断とあわせて決める |
| フックの判定を機械検査にするか | `.claude/hooks/protect-config.sh` と `block-dangerous-git.sh` は、守る側と通す側のペイロードを手で流して確かめている。検査として足すなら、ペイロードと期待する判定の対を置く場所と、どの検証コマンドで走らせるかを決める必要がある。検証コマンドを増やすと `.github/workflows/` の変更になり、ユーザーの承認が要る([ADR-0025](../adr/0025-permission-policy-guard-in-hooks.md)) |
| `test_excluded` に理由を要求する仕組み | 名前を足して同時に `build.zig` の `targets` から外すと、検証コマンドはすべて緑のままそのファイルのテストが走らない。意図された脱出口だが、2件目以降が1件目と同じ正当性を持つかを検査する手段が無い。除外の理由を文書の表に書かせ、`check-docs` が `--exclude` ごとに行の存在を照合する案を、`src/wasm.zig` を除外する段階1で試す |
| 字句アドレスの深さと添字のビット幅、または実装制限として報告する閾値 | 16MBのヒープ内で作れる入れ子の深さ。16ビットでは溢れるので32ビットにするか報告する |
| ヒープ外ペイロードと所有者の確保の巻き戻しの単位 | 失敗時に計上が失われない形。`heap.zig` のコメントに書く |
| 予約領域の具体的なバイト数 | [runtime.md](runtime.md) の必要量の表を実測で埋める |
| フレーム数に上限を設けるかどうか、設けるなら設定手段 | 計上の上限と二重になるため、どちらが先に効くかを実測して決める |
| GCの起動の閾値(計上量に対する割合) | 段階1のベンチマークで決める |
| 作業リストの予約サイズ | 上限に比例した係数を実測で決める |
| WASM の出力バッファの初期サイズと伸ばし方 | Web UI の体感で決める |
| Web UI をローカルで開く手段と、PR の zip を開く手段 | `file://` から始まる取得は Fetch の対象外なので、`.wasm` もモジュールスクリプトも Worker も取得できない。ローカルの HTTP サーバを立てる形に絞られる。`zig build` の step で立てる形と、zip にサーバを同梱する形のどちらにするかを決める。zip を開くレビュアに何を要求するかが決まるので、2つを一緒に決める。段階1の計画で決める([ADR-0021](../adr/0021-no-github-pages-defer-hosting.md)) |
| 内部値(未束縛、未初期化)の表現 | 即値の枠を使うか専用のヒープオブジェクトにするか。段階1の実装で決める |
| Windows の引数と環境変数を UTF-16 から変換したときの不対サロゲートの扱い | Zig 0.17.0 の変換 API を実機で確認し、[zig-api-notes.md](zig-api-notes.md) に記録する。検証が必要なら [platform-and-web.md](platform-and-web.md) の表に従って拒否する |

## 段階2までに決める

| 事項 | 根拠にするもの |
| --- | --- |
| `syntax-rules` の照合結果(パターン変数の束縛木)の表現 | 省略記号の深さに応じた木。段階2の実装で決める |
| 別名の印の表現と、周回しないことの保証 | 固定幅の通し番号なら周回で衛生性が壊れる。幅を広げるか、上限に達したらエラーにするか、オブジェクトの同一性にするかを段階2の実装で決める |
| 構文環境の束縛の探索方法(線形探索かハッシュ) | 束縛数の実測。多くの場合少数と見込んでいる |
| 探索ディレクトリの設定手段 | ライブラリ名、`include`、`load` の3経路で同じ手段にする。環境変数かコマンドライン引数か両方かを段階2で決める。R7RS 4.1.7 の Note が利用者による指定の手段を推奨している |
| リンクと reparse point の追跡を禁止してファイルを開く手段 | Zig 0.17.0 の `std.Io.Dir` の API を実機で確認し、[zig-api-notes.md](zig-api-notes.md) に記録する |

## 記録の規約

- 段階の完了時に、その段階の行をこのファイルから消す。消す前に、決めた内容を該当する設計ドキュメントまたはコードのコメントに書く。
