# 6 Web UI

sucheme は、WebAssembly にして、ブラウザの上でも動かせます。ここでは、手元で開く方法と、実行ファイルとの違いを説明します。ブラウザでの表示は、この文書を書くときに確かめていません。ここに書くことは、リリースノート([v1.0.0](../../releases/v1.0.0.md) の「使い方」)とソースから確かめたものです。

配置した URL は、まだありません([ADR-0021](../../adr/0021-no-github-pages-defer-hosting.md))。ローカルで開く形だけです。

## ローカルで開く

リリースの `sucheme-web-v<版>.zip` を展開し、できたディレクトリで、次を実行します。Node.js が要ります。

```text
node serve.mjs
```

表示された `http://127.0.0.1:<ポート>/` をブラウザで開きます。`file://` で `index.html` を直接開いても、動きません。ブラウザが、WebAssembly とワーカーを読み込ませないからです。

ソースから作るときは、`zig build wasm` で `zig-out/web/sucheme.wasm` を作り、リポジトリの根で `node web/serve.mjs` を実行します。ポートとディレクトリは、引数で変えられます([web/serve.mjs](../../../web/serve.mjs) の冒頭)。

## できること

- 選んで実行できるサンプルがあります([web/samples.mjs](../../../web/samples.mjs))。
- 入力したソースを URL のフラグメント(`#code=...`)に入れた共有リンクを作れます。
- 入力欄には、編集の補助があります。カーソルの隣の括弧と、その相手の括弧が強調されます(文字列、文字、コメント、`|` で囲んだ識別子の中の括弧は数えません)。Tab で字下げが入り(2文字の空白)、複数行を選んで Tab を押すと、掛かる行すべてが字下げされます。Shift+Tab で取れます。Tab を字下げに使うので、キーボードで入力欄から出るときは、Esc のあとに Tab(後ろへ出るときは Shift+Tab)を押します。
- 実行した入力は、このページを開いている間、履歴に残ります(最大100件。ページを閉じると消えます)。最初の行にカーソルがあるときの上矢印で1つ前の入力に、最後の行にあるときの下矢印で1つ後の入力に移ります。履歴をたどる前に入力していた文字列は、いちばん新しい入力のさらに下矢印で戻ります。
- エラーになると、それまでに出た出力は出力欄に残り、エラーの説明は、その下の別の欄に出ます。`exit` を呼んだときは、終了コードが同じ欄に出ます。通常のエラーのあとは、続けて評価できます。回復できないエラーと `exit` のあとは、画面の「Reset」ボタンを押すまで、評価できません。

- 実行時のエラーに位置があるとき(`wrong type of argument to car 5` のように、手続きの呼び出しが送出した誤り)は、エラーの説明が `行:桁:` で始まり、入力欄の、誤りを起こした呼び出し(開き括弧から対応する閉じ括弧まで)が、色と波線の下線で強調されます。行と桁は1から数え、桁は文字で数えます(日本語や絵文字を含む行でも、文字ごとに1桁です)。入力欄を編集すると、強調は消えます(位置が、実行したときの入力に対するものだからです)。再び実行すると、前の強調は消えます。位置の無い誤り(未束縛の変数、標準ライブラリの手続きの中の誤りなど)は、説明だけが出て、強調はありません。強調が入力欄の見える範囲の外にあるときは、入力欄がスクロールします。画面の見え方は、Chromium で確かめました。他のブラウザは確かめていません。
- 評価中は、経過時間が「Elapsed」として画面に出ます。評価が終わるか止めると、表示は消えます。
- 評価は、歩数ごとに区切って進むので、長い評価の間も、画面は応答します。
- 評価中は、「Stop」ボタンか `Esc` キーで止められます。止めると、いま走っている評価だけが捨てられ、それまでに定義したものは残ります。止めるまでに出た出力は、出力欄に残り、止めるまでにかかった時間が、その下の欄に出ます。評価中は、定義が残ることを「Stop」の近くに前もって表示します。日本語の入力の変換中の `Esc` は、停止になりません。
- 評価が止まるのは、歩数の区切りです。区切りの間に走る処理は、「Stop」を押しても、終わるまで止まりません。たとえば、`import` で読み込むライブラリの本体と、1歩の中で長く走る組み込みの手続き(巨大なベクタの作成や `vector-fill!`、巨大なデータへの `equal?` など)がそうです。そのような処理が長引くと、3秒たっても応えないので、処理系を作り直します。そのとき、それまでに定義したものはすべて失われ、出力欄にそのことが出ます。区切りの間隔が、1歩の長さに引き延ばされることは、Node.js 上で確かめました(8百万要素のベクタの作成と `vector-fill!` を含む入力が、1つの区切りで走り、約0.2秒、制御を返しませんでした)。3秒での作り直しは、ブラウザでは確かめていません。

## 実行ファイルとの違い

Web UI では、`display` などの出力も、エラーポートへの出力も、結果と同じ欄に出ます。ファイルは開けません(`file-error` になる)。標準入力は、画面の入力欄から渡します(次の「`read` による対話」)。

配置した URL は、まだありません([7 準拠の状況と既知の制限](07-limitations.md))。

## `read` による対話

`(read)`、`(read-line)`、`(read-char)` などが、渡された入力を使い切って次の入力を待つと、評価はそこで止まり、出力欄のすぐ下に「Input for the program」の入力欄が出ます。入力欄にはフォーカスが移ります。出力欄には、それまでの出力(たとえば `(display "name? ")` の問い)が出ています。

- 1行を渡す: 入力して `Enter` を押すか、「Send」を押します。行の終わりに改行が付いて渡るので、`read-line` は、入力した行を返します。何も入力せずに押すと、空の行が渡ります。渡した行は、端末のエコーと同じく、出力欄にも写ります。この写しは、評価の結果の出力に含まれます。
- 入力を終える: 「End of input」を押すか、入力欄で `Ctrl+D` を押します。待っていた読み取りは、ファイルの終わり(`#<eof>`)を受け取ります。終わりを渡したあとは、続く読み取りもすべて、待たずにファイルの終わりを返します。この状態は、画面の「Reset」を押すまで残ります(次の評価にも続きます)。画面には、そのことを知らせる文が出ます。
- 止める: 入力を待つ間も、「Stop」ボタンか `Esc` キーで評価を止められます。止めたときの扱いは、評価中と同じです(それまでの出力と定義は残ります)。入力欄は閉じます。
- 括弧が閉じていない `(read)` のように、1回に渡された入力では読み終えられないときは、続きの入力をまた待ちます。
- 渡した入力のうち、1回の読み取りが使わなかった分は、次の読み取りが先に取ります。たとえば `(read)` に `(1 2 3)` を渡すと、行の終わりの改行が残るので、次の `(read-line)` は、待たずに空の行を返します。続きの行から読みたいときは、`read-line` を1回余分に呼ぶか、「Reset」で捨てます。
- 入力欄で渡せるのは1行です。複数の行を渡すときは、1行ずつ渡します。
- 入力欄の行は、実行した入力の履歴(上矢印と下矢印)には入りません。
- 評価が終わると、入力欄は閉じ、フォーカスはソースの入力欄に戻ります。
- 待っている間も、経過時間は進みます。
- 日本語などの入力の変換を確定する `Enter` では、送信しない作りにしています。実際の変換での動作は、確かめていません(日本語の文字列を入力欄に入れて送ることは、Chromium で確かめました)。

Web UI のテストは、WebAssembly のエクスポートを Node.js から呼ぶものだけです。ブラウザ固有の問題は、自動では見つかりません(リリースノートの「動作保証の範囲」にあります)。
