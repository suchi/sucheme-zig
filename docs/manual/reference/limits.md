# 実装の上限

sucheme が、R7RS の言う「実装の制限」として持つ上限をまとめます。上限は、超えたときに何が起こるかと一緒に書きます。例は `check-examples` が走らせ、挙動が変わると赤くなります。R7RS が実装に委ねている点については、原文の 1.3.2 節(誤りの状況と未規定の振る舞い)と 6.2.3 節(数の実装の制限)を参照してください。

## ヒープの上限

プログラムが使うオブジェクト(ペア、文字列、ベクタ、クロージャ、呼び出しの途中経過など)の合計には、上限があります。実行ファイルの既定は 256 MiB です(値の正は `src/heap.zig` の `default_limit` です)。上限を超える確保が必要になると、まずごみ集めを行い、それでも足りなければ `heap limit exceeded` の誤りになります。

誤りは `error:` の行として出て、その式(最上位の形式)の評価だけが終わります。REPL は止まらず、ヒープは次の式から使えます。

1 つの確保が、ヒープの残りに収まらないときが、最も早く確かめられる例です。

```scheme fresh
(make-vector 1000000000 0)
```

```output
error: heap limit exceeded
```

小さな確保を重ねて上限に届く場合も、同じ誤りです。たとえば `(define (grow acc) (grow (cons 1 acc)))` のあとに `(grow '())` を呼ぶと、リストが伸び続けて上限に届きます。実機の例が上限に届くまでの時間は長く、この文書の検査には載せていません(下に測った時間を書きます)。

誤りの後の式は、REPL では次の入力として評価されます(1 つのコードブロックは、最初の誤りで終わるので、ブロックを分けて書いています)。

```scheme
(+ 1 2)
```

```output
3
```

ファイルの実行では、実行時エラーと同じく、`error: heap limit exceeded` を標準エラーに出して、プログラムを終了コード 1 で止めます([ユーザーズガイド 2 コマンドライン](../guide/02-command-line.md))。この誤りは、`guard` で受けられます。条件オブジェクトのメッセージが `heap limit exceeded` になります(実機で、`(guard (e (#t (error-object-message e))) (grow '()))` が `"heap limit exceeded"` を返すことを確かめました。上限に届くまで時間がかかるので、この文書の検査には載せていません)。

上限に届くまでの時間は、確保の仕方で大きく違います。Linux で測った一例では、上の `grow` が上限に届くまでに、Debug のビルド(`zig build` の既定)で約 55 秒、ReleaseSafe のビルドで約 38 秒かかりました。

## 再帰の深さ

末尾でない再帰の深さに、固定の上限はありません。呼び出しの途中経過はヒープに置かれ、ヒープの上限までは深く潜れます。100 万段の再帰が動きます。

```scheme fresh
(define (depth n) (if (= n 0) 0 (+ 1 (depth (- n 1)))))
(depth 1000000)
```

```output
1000000
```

深さが上限を超えると、スタックが溢れるのではなく、上のヒープの上限の誤りになります(実機で、`(depth 100000000)` が `error: heap limit exceeded` になることを確かめました。上限に届くまで時間がかかるので、この文書の検査には載せていません)。

末尾呼び出しは、深さを増やしません。ループは、回数に上限なく回ります(R7RS 3.5 節)。

```scheme fresh
(define (loop n) (if (= n 0) 'done (loop (- n 1))))
(loop 3000000)
```

```output
done
```

## 入力の大きさ

入力の大きさの上限は、読む経路ごとに決まっています。

- REPL: 溜めている入力(継続行を含む)の合計が、改行を含めて 65536 バイトまでです。超えると `error: the input does not fit in 65536 bytes, newline included` を出して、溜めた入力を捨てます。例は [ユーザーズガイド 3 REPL](../guide/03-repl.md) にあります。1 行だけで収まらないときは `error: the line does not fit in 65536 bytes, newline included` です。
- ファイルの実行: プログラムのファイルは 1 MiB までです([ユーザーズガイド 4 ファイルの実行](../guide/04-running-files.md))。
- ライブラリのファイル: 同じく 1 MiB までです。

値は `src/main.zig` の `max_line` と `max_program_bytes` が正です。

## 実行歩数の上限

最上位の形式ごとの歩数の上限を設ける仕組みが、組み込みの API にありますが、実行ファイルの既定は上限なしです。止まらないプログラムは、止まりません(Ctrl-C などで止めます)。上限は、準拠スイートの実行器が、止まらないテストを打ち切るために使います。
